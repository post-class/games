### ⚠️ 判明した重要な制約（設計に反映済み）

1. **`temperature` が使えない**（`gpt-5.6-luna` は既定値1のみ）
   → 発話の多様性はプロンプト（ペルソナ・記憶・気分）で作る
2. **`max_tokens` は不可**。`max_completion_tokens` を使う
3. `json_schema`(strict) / `json_object` / `stream` は利用可。初トークン 約0.7〜0.9秒
4. **Node の type-stripping で動かすため TS の一部構文が使えない**
   - parameter property（`constructor(private x: T)`）→ 使用禁止
   - enum / namespace → 使用禁止（`as const` + union type で代替）
   - 相対importは拡張子 `.ts` 込みで書く

### ⚠️ バランス調整で見つけた実装バグ（すべて修正済み）

長時間シミュレーションを回して初めて分かったもの。**単体テストでは絶対に見つからなかった**。

1. **ほぼ空の資源を選び続けて餓死する**（最重要）
   `findNearestResource` が「在庫 > 0」で最も近いものを返すため、0.1しか残っていない木に通い続け、
   少し離れた満タンの木へ行かなかった。冬に半数が死ぬ原因。→ `minAmount` 引数を追加して解決
2. **雨の夜に立ったまま眠れない**
   「木の下へ移動」候補が距離0でも満点を取り続け、睡眠に勝っていた。→ 到着後は候補を出さない
3. **長雨で木の下から出ずに餓死する**
   避難のスコアが空腹に負けない設計だった。→ 空腹の切迫度で避難の魅力を下げる
4. **寝ているいのししから逃げ続ける**
   逃走が評価の8%を占め、夜の睡眠率が落ちていた。→ 寝ている相手は脅威にしない／寝ている個体は至近距離でしか起きない
5. **交流の好感度が育たず子が1匹も生まれない**
   7島日で友達4組。個体は寿命で減るだけになり「世代が続く島」が成立しなかった。
   → `socializeGain` を上げ、近くにいるだけでも馴染む `proximityGain` を追加
6. **食料が需要の5倍あり、取り合いが起きない** → 資源の回復量を絞った
7. **増えすぎた島は冬を越せない**（上限150で試したら150→24体に崩壊）→ 上限120 ＋ 食料に応じた出生率
8. **同じペアが延々ケンカしてログが埋まる**（冬に1島日2500件）→ ペアごとに1島時間のクールダウン

### バランス定数の最終値（`shared/constants.ts` に集約）

| 項目 | 値 | 理由 |
|---|---|---|
| `INITIAL_CRITTERS` | 70 | 90だと収容力超過で開始直後に40体が餓死した |
| `MAX_CRITTERS` | 120 | 150だと秋に増えすぎて冬に崩壊した（性能の安全弁でもある） |
| `berryRegenPerIslandHour` | 0.15 | 0.6だと供給が需要の5倍で取り合いが起きない |
| `winter.regen` | 0.5 | 設計書どおり。分布バグを直したので厳しくても耐えられる |
| `socializeGain` / `proximityGain` | 1.4 / 0.02 | 群れと繁殖が成立する速さ |
| `breedFoodPerCapita` | 9 | 個体数の上限より先に食料が効くように |
| `starvationHealthPerIslandHour` | 4 | 8だと冬に死が連鎖して下限40を割った |

### 現在の生態サイクル（28島日・seed=winter-check）

```
春 70体 →（春夏で繁殖）→ 120体 → 秋は資源が潤沢 → 冬に資源が1045→459へ半減
→ ケンカ8.6件/日（秋の8倍）・餓死は1体のみ → 春に回復
```

### M4以降への申し送り

1. **個体数は秋以降120（上限）に張り付く**。上限が実質的に夏〜秋の収容力になっている。
   気になるなら食料の回復量をさらに絞るが、そうすると冬の死亡が増えるトレードオフ
2. 荒廃タイル率は最大0.7%。「荒らした畑は戻るのに時間がかかる」は仕組みとしては動いているが**目に見えない**。
   M7でプレイヤーの収穫が入ってから再調整する
3. `critter.ts` の `WEIGHTS` はまだ critter.ts 内にある（`constants.ts` へ移すのが本来の形）
4. **巣（nest）タイルは WeakMap 保持で再起動すると忘れる**。永続化したいなら `Actor` に持たせる必要がある
5. `CritterAI.stats().switched` は「行動が完了して再発行した」ケースも数える（純粋な心変わりの回数ではない）
6. 動物の初期配置は種ごとに均等（`i % 6`）。比率を変えたいなら重み付けが必要

## M1 の実装記録

### サーバ側

- `sim/world.ts`：世界の器（タイル・アクター・資源・設置物とアクセサ）
- `sim/worldgen.ts`：value noise → radial falloff → しきい値 → 広場 → 土 → flood fillで孤島を沈める → 資源配置
  - 実測: 生成 約30ms、歩けるタイル率 39.7〜48.4%（20 seed）、到達不能な陸 0、資源は全種類配置
- `sim/actors.ts`：プレイヤー/動物/ペットの生成、traits の生成と遺伝、`actorToWire`
- `sim/nav.ts`：8方向A*（角抜け禁止・octile）、12タイル以内は直進、1tick最大8件のキュー
- `sim/movement.ts`：経路追従・軸入力・押し出し衝突・地形と境界の制約
- `net/sync.ts`：興味管理つき chunk / snapshot / delta 生成
- `sim/island.ts` / `net/hub.ts`：上記の配線（tick順序 = clock → nav → movement → hooks → delta送信）

### 結合の実測（サーバ単体）

- WS接続 → welcome（spawn=広場の中心 64.5,64.5）→ chunk 2枚 → snapshot → delta 4Hz
- `move` を送ると A* で経路が引かれ、実際に 9.6タイル移動した
- 切断で アクター・nav・sync のクリーンアップが動作（actors=0 に戻る）
- tick処理時間 p50 0.02ms / p95 0.19ms（アクター1体）
- サブエージェント計測: 120体+16接続で 合計 p50 0.26ms / p95 1.33ms、帯域 約5.4KB/秒/人

### クライアント側

- `render/tilemap.ts`：チャンク（16×16）をRenderTextureへ焼成。荒廃度フックあり（M3で実装）
- `render/camera.ts`：デッドゾーン追従・ズーム3段（0.75/1.0/1.5）・島端クランプ・座標変換
- `render/sprites.ts`：150ms補間バッファ・y座標での深度ソート・culling・自機のクライアント予測
  （ズレ0.5タイルで0.2秒補正、3タイルで即スナップ、**入力中は補正しない**）
- `render/effects.ts`：時間帯の色被せ
- `state/world.ts`：snapshot/delta/chunk の適用（Pixi非依存なのでテストしやすい）
- `input.ts`：WASD・クリック移動・ホイールズーム
- `dev/mock.ts`：`?mock=1` でサーバなしに描画だけ検証できる（本番バンドルには入らない動的import）
- `tools/placeholder.ts`：PNGを自力エンコード（依存追加なし・決定論）。本番アセットは同じパスに差し替えるだけ
