# 03 タスク詳細（実装方針・触るファイル）

`02_是正プラン.md` の各IDに対応する具体策です。実装時の迷いを減らすためのメモで、
**手を動かす前にここを読み、終わったら分かったことを追記**してください。

共通の前提:

- 追加アセットは `img-gen-gpt` スキルで生成 → `tools/install-assets.py` の後処理（切り出し・
  48px/32pxへ縮小・足元揃え・`_w` は `_e` の反転）に乗せる。採用プロンプトは `tools/gen-assets.md` に追記する
- プレースホルダは `node tools/placeholder.ts`（決定論）。**新しいアセット名を足したら
  プレースホルダ側にも足す**（`render/assets.ts` は1枚ずつ受け止めるので欠けても落ちないが、
  欠けたまま気づかないのを避けるため）
- 初回ロードの制約（画像239KB / 合計430KB / 0.65秒）に対し**まだ余裕がある**。
  それでも枚数が2倍を超えるならアトラス化を検討する

## A. 方針決定

### A-1 視点の方針

**推奨: トップダウンを維持し、絵柄で"斜め見下ろし"の印象を作る。**

理由:

- クォータービュー化は `tilemap.ts`（チャンクのRenderTexture焼成）・`camera.ts`（座標変換）・
  `sprites.ts`（深度ソート）・`minimap.ts`・`movement.ts` の当たり判定・
  既存アセット62枚の全部が作り直しになる。M0〜M8と同規模の作業
- 一方、**印象の差は視点そのものより「地面の情報量」「影」「演出」から来ている**。
  宣伝ヒーロー画像を見ても、"斜め"より"密度"と"手描きの色ムラ"が効いている

やること:

1. オブジェクト（家・風車・井戸・噴水・木）を**軽い斜め見下ろし**で描き、
   キャラは正面顔のまま、影を足す。これだけで"クォータービュー風"に読める
2. 宣伝資料 `index.html` の `<b>GRAPHICS</b>` を
   `2D トップビューの手描き風タイル` に直す（→ H-1）
3. 決定を `04_スタイルガイド.md` §1 に残す（このプランは docs/03 だけで完結させる）

### A-2 スタイルガイド

`04_スタイルガイド.md` を新規作成し、次を数値で固定する。

- パレット: 宣伝資料 `index.html` の `:root` の値をそのまま採用
  （`--grass #d9ee94` / `--ink #4a3b2a` / `--purple #a892e0` / `--peach #ffb9a3` / `--sky #9fd8ee` / `--mint #a8e0b4` / `--cream #fffdf3`）
- 線: 濃い茶（`--ink`）の輪郭、48px枠で2〜3px相当
- 影: 足元の楕円、`rgba(74,59,42,0.18)`、幅=キャラ幅の0.6倍
- 彩度: M8で草地・森タイルをHSVのSだけ0.78倍している。**この処理を全タイルの基準にする**
  （M8申し送りの「`tile_dirt` も彩度が高め(0.687)」もここで揃える）
- 足元合わせ: `install-assets.py` の既存ルールを踏襲

## B. 地面

### B-1 タイルのバリエーション

- ファイル名を `tile_grass.png` → `tile_grass_0..3.png` に拡張（`tile_grass.png` は残して後方互換）
- `tilemap.ts` の焼成ループで、タイル座標から決定論的に variant を選ぶ
  （`shared/rng.ts` の hash を使う。**`Math.random` は使わない**。同じseedで同じ絵になることが M1 の完了条件）
- テスト: 既存の「サーバ再起動をまたいでチャンクのハッシュが一致」に、variant index を含めた比較を追加

### B-2 遷移タイル（autotile）

- 方式は **4-bit（上下左右の隣接）+ 角4bit の簡易 blob**。16枚/境界で足りる
- 必要な境界: 草↔砂、砂↔水、草↔森、広場↔草
- `tilemap.ts` は既にチャンクをRenderTextureへ焼いているので、**焼成時に遷移タイルを上書き描画**すればよい。
  ランタイムのコストは増えない
- **地形が変わったら焼き直す**必要がある（橋の完成で `terrainChanged` が来る。M7で実装済みの再取得経路に乗る）

### B-3 装飾デカール層

- `stage.ts` に `decal` レイヤが**既に用意されていて誰も使っていない**（`stage.ts:37`）。ここに置く
- 配置は worldgen と同じ value noise から決定論的に。**サーバに持たせない**（見た目だけなのでクライアント計算で十分。
  帯域も増えない）
- 種類: 草の房・小花（白/黄/桃）・小石・落ち葉・きのこ・切り株。草地には密に、砂には疎に
- 歩行判定には**影響させない**（`movement.ts` は触らない）

### B-4 海のアニメーション

- `weather.ts` と同じ作り（1枚の `Graphics` に線をまとめる）で、海岸線に沿った白線を2秒周期で動かす
- 浅瀬は海タイルのうち「陸に隣接するもの」を明るい色で焼く（B-2 の遷移タイルで兼用できる）
- `prefers-reduced-motion` で停止（`weather.ts` の既存判定を流用）

### B-5 木のバリエーション

- `obj_berry_tree_{full,empty,young,dead}.png`
- `objects.ts` の `place()` に渡すキーを在庫量で切り替える。いまの `alpha 0.65` はやめる

## C. 暮らしの痕跡

## F. 演出

### F-1 夜

- `render/effects.ts` の `TOD_TINT.night` を `alpha 0.3` → 0.5前後へ。色は紺（`0x24356e`）のまま
- 星空と月を `overlayRoot` に足す（カメラ非依存でよい。1枚のGraphics）
- ⚠️ 暗くするとキャラが読めなくなる。**F-2 の光源を先か同時に**入れて、光の周りだけ抜く
- ⚠️ 時間帯の切り替えは `k = dtSec * 1.5` で補間している。急に暗くしないこと

### F-2 光源

- `entities` の上に加算ブレンドのレイヤを1枚。ランタン・焚き火・家の窓・天文台に光の玉を描く
- 夜と夕だけ有効。昼は描かない（コストゼロ）
- 光の強さは `prefers-reduced-motion` でも変えない（明滅だけ止める）

### F-3 雨

- `weather.ts`: 粒を増やし、**地面の濡れ（暗いtint）と水たまりの波紋**を足す。
  スマホは既に粒を1/3にしているのでその係数を維持
- `audio.ts` は音源ファイルを持たずWebAudioで合成している。**雨音はノイズのフィルタで作れる**（追加アセット不要）
- 霧・曇りも同じ機会に調整

### F-4 季節

- 安く出せる分: タイルの tint（春=やや明るい／夏=濃い緑／秋=黄橙／冬=白寄り）
- アセットが要る分: 秋の紅葉した木、冬の雪タイルと枯れ木、春の花が咲いた木
- 季節は `clock` から来ているので配線は済んでいる（`effects.ts` に季節を渡すだけ）
