# 05. 通信プロトコル

## 1. 前提

- WebSocket 1本。JSONテキストフレーム（MVP）。
  帯域が問題になったら MessagePack ＋ 座標の固定小数点化に切り替える（`11_リスクと決定事項.md` ADR-005）。
- すべてのメッセージは `{ t: string, ... }` 形式。`t` はメッセージ種別。
- zodスキーマを `packages/shared/src/protocol.ts` に定義し、**受信側は必ずparseしてから使う**。
  クライアント発のメッセージを信用しない（座標を直接書き込ませない）。

## 2. 接続シーケンス

```
client                                  server
  │  GET /ws?v=1                          │
  ├──────────────────────────────────────►│
  │  {t:'hello', secret?, displayName?}    │
  ├──────────────────────────────────────►│
  │                                        │ 認証 or 新規プレイヤー作成
  │  {t:'welcome', playerId, entityId,     │
  │   islandId, seed, clock, you, pet?}    │
  │◄──────────────────────────────────────┤
  │  {t:'chunkReq', chunks:[...]}          │
  ├──────────────────────────────────────►│
  │  {t:'chunk', cx, cy, terrain, res[]}   │  ×N
  │◄──────────────────────────────────────┤
  │  {t:'snapshot', tick, actors[], ...}   │  初回フル
  │◄──────────────────────────────────────┤
  │  {t:'awaySummary', lines[]}            │  留守中サマリ
  │◄──────────────────────────────────────┤
  ─────────── 以降 delta / 入力 の往復 ───────────
```

ペット未作成なら `welcome.pet == null` → クライアントはタマゴ選択画面を出し、
`{t:'createPet', species, name, persona}` を送る。

## 3. クライアント → サーバ

| `t` | ペイロード | 説明 |
|---|---|---|
| `hello` | `{secret?: string, displayName?: string}` | 匿名認証。secretがなければ新規発行して返す |
| `chunkReq` | `{chunks: [cx,cy][]}` | 視界に入ったチャンクの地形要求（未受信のみ） |
| `move` | `{to: Vec2}` | 移動目標タイル（クリック移動）。サーバがA*で経路化 |
| `moveAxis` | `{dx: -1..1, dy: -1..1}` | キー入力方向（100msごとに変化時のみ送信） |
| `interact` | `{targetId: EntityId, act: 'harvest'\|'water'\|'pet'\|'talk'}` | 距離チェックはサーバで行う |
| `say` | `{text: string(≤200), to?: EntityId}` | ペットへの発話。`to`省略時は近くの自ペット |
| `place` | `{type, pos}` | 設置物 |
| `contribute` | `{constructionId}` | 共同建設への貢献 |
| `createPet` | `{species, name(≤12), persona}` | 初回のみ |
| `ping` | `{ts}` | RTT計測（5秒ごと） |

### レート制限（サーバ側で強制、超過は破棄しwarnを返す）

| メッセージ | 上限 |
|---|---|
| `move` / `moveAxis` | 20/秒 |
| `interact` | 4/秒 |
| `say` | 1/2秒 かつ 60/時（LLM保護。`07_ペットAI設計.md`の予算と連動） |
| `place` | 1/秒 かつ 30/時 |
| `chunkReq` | 8/秒 |

## 4. サーバ → クライアント

| `t` | ペイロード | 頻度 |
|---|---|---|
| `welcome` | `{playerId, secret, entityId, islandId, seed, clock, you, pet}` | 接続時1回 |
| `chunk` | `{cx, cy, terrain: number[](RLE), resources: ResourceNode[]}` | 要求時 |
| `snapshot` | `{tick, clock, actors: ActorWire[], resources[], placeables[]}` | 接続時＋再同期時 |
| `delta` | `{tick, upd: ActorDelta[], add: ActorWire[], rm: EntityId[], res?: ResDelta[], clock?}` | 4Hz |
| `bubble` | `{entityId, text, kind:'say'\|'think', ms}` | 発生時 |
| `chatChunk` | `{convId, entityId, delta: string, done: boolean}` | LLMストリーミング |
| `notice` | `{text, importance}` | 近くの出来事 |
| `awaySummary` | `{lines: string[], islandDaysPassed}` | 接続時 |
| `petState` | `{affection, intent?: {goal, reason}, mood}` | 変化時 |
| `warn` | `{code, message}` | 不正/レート超過 |
| `serverClosing` | `{reason}` | 停止時 |

### ワイヤ形式（`ActorWire`）

送信量を抑えるため、名前や種別は追加時（`add`）だけ送り、更新（`upd`）は差分だけ送ります。

```ts
type ActorWire = {
  i: EntityId; k: 0|1|2;      // 0=critter 1=pet 2=player
  s: string;                  // species
  n: string;                  // name
  x: number; y: number;       // 小数2桁に丸めて送る
  f: 0|1|2|3;                 // facing n/e/s/w
  a: number;                  // anim enum
  o?: string;                 // ownerId（pet時）
};

type ActorDelta = {
  i: EntityId;
  x?: number; y?: number; f?: number; a?: number;
};
```

## 5. 興味管理（interest management）

全120体＋他プレイヤーを常に送ると無駄なので、**視界＋マージン**に限定します。

```
視界: 画面サイズから算出（最大 40×24 タイル）
配信範囲: 視界を1チャンク（16タイル）分広げた矩形
```

- プレイヤーごとに「前回送った状態」を `Map<EntityId, ActorWire>` で保持
- 範囲に入った → `add` / 出た → `rm` / 中にいる → 変化分のみ `upd`
- 位置は0.02タイル以上、animやfacingは変化時のみ差分に含める
- **自分のペットは範囲外でも常に送る**（ペットが遠くで何をしているか見えると楽しいので、ミニマップに出す）

帯域見積り: 画面内80体 × 平均12B × 4Hz ≒ **3.8KB/秒/プレイヤー**。16人で60KB/秒。十分軽い。

## 6. クライアント側の補間

- 受信スナップショットを **150msのバッファ**に積み、描画は `now - 150ms` の時点を線形補間する
- 自分のアバターのみクライアント予測：入力で即動かし、サーバ値と0.5タイル以上ズレたら0.2秒で補正移動
- 3秒以上deltaが来なければ「接続不安定」を表示し、5秒で再接続 → `snapshot` から復帰

## 7. 再接続

```
close → 指数バックオフ（0.5s, 1s, 2s, 4s, 上限8s）で再接続
  → hello(secret) → welcome → 保持済みチャンクはchunkReqしない → snapshot
```

`secret` は `localStorage` に保存。プレイヤーIDの引き継ぎに使い、失効時は新規プレイヤーとして扱う。

## 8. HTTPエンドポイント

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/` | クライアント配信（本番はViteビルド成果物を静的配信） |
| GET | `/healthz` | 死活監視 |
| GET | `/metrics` | 開発時のメトリクス（本番は無効） |
| GET | `/ws` | WebSocketアップグレード |

LLMを叩くエンドポイントは**公開しない**。会話は必ずWS経由（`say` → `chatChunk`）で、
サーバ側でプレイヤーとペットの紐付けと予算を検証してから実行します。
