# 02. 技術スタックとアーキテクチャ

## 1. 技術選定

| レイヤ | 採用 | 理由 |
|---|---|---|
| 言語 | TypeScript 5.7（strict） | 要件。クライアント／サーバで型を共有できる |
| パッケージ管理 | npm workspaces（npm 11 / Node 24） | 追加ツール不要。既存の `multi-commander` と同じ流儀 |
| クライアントビルド | Vite 6 | `multi-commander` で実績あり。HMRが速い |
| 2D描画 | **PixiJS v8** | WebGL/WebGPUバッチング。透過PNGスプライトを数百枚出しても軽い。ParticleContainerとtilemap的な使い方が容易 |
| サーバHTTP | **Hono** | 軽量・型が素直・Node/他ランタイム両対応 |
| サーバWS | **ws** | 素のWebSocket。プロトコルを自前で握れる |
| 永続化 | **SQLite（better-sqlite3）** | 単一プロセス常駐・同期API・トランザクションが速い。運用がファイル1個で済む |
| スキーマ検証 | **zod** | プロトコル境界とLLM出力の検証を同じ書き方で行える |
| LLM | Azure OpenAI `gpt-5.6-luna`（`2025-04-01-preview`） | 要件。`fetch` で直接叩く（SDK依存を増やさない） |
| 単体テスト | Vitest | `multi-commander` と同じ |
| E2E | Playwright（既存MCPと同じブラウザ） | 2ブラウザ同時接続テストとスクリーンショット確認 |
| アセット生成 | img-gen-gpt スキル | 透過PNGが作れる（要件） |

### 採らなかった選択肢

- **Phaser** — シーン管理やArcade物理は今回不要で、描画以外が重い。Pixi＋自前ECSの方が制御しやすい。
- **Colyseus / socket.io** — 状態同期の抽象が便利だが、興味管理とスナップショット差分を自分で設計したいので素のwsにする。
- **Postgres** — 単一島インスタンスの規模では過剰。将来シャードを複数ホストに分ける段階で再検討（`11_リスクと決定事項.md` ADR-004）。
- **クライアント直LLM呼び出し** — APIキー露出のため論外。

## 2. 全体構成

```
┌────────────────────────── ブラウザ (client) ─────────────────────────┐
│  PixiJS 描画  ←  補間バッファ  ←  WebSocket  →  入力コマンド        │
│  DOM UI（チャット・ペット設定・留守中サマリ）                        │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ WebSocket (JSON)
┌──────────────────────────────┴──── Node 常駐プロセス (server) ──────┐
│                                                                     │
│  ConnectionHub ── 興味管理 / スナップショット差分生成                │
│        │                                                            │
│  IslandSim  ← 4Hz tick ─┬─ WorldClock（時間・季節・天気）            │
│  (権威状態)             ├─ ResourceSystem（資源の枯渇と回復）        │
│                         ├─ CritterAI（動物のユーティリティAI）       │
│                         ├─ RelationSystem（好感度・繁殖・寿命）      │
│                         ├─ PetActionSystem（ペットの行動実行）       │
│                         └─ EventBus（出来事 → 記憶/通知）            │
│        │                                                            │
│  PetBrain（非同期・tick外）──→ LLMClient ──→ Azure OpenAI            │
│        │         ↑ 記憶検索                                         │
│  MemoryStore ─── SQLite (island.db)                                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 設計の柱

1. **シミュレーションは同期・LLMは非同期。**
   tickループの中でLLMを待つことは絶対にしない。`PetBrain` はtick外で走り、
   結果を「次の目標（intent）」としてキューに積むだけ。シミュレーションは常に一定速度で進む。

2. **サーバ権威。**
   クライアントは入力（移動先・インタラクト・発話）を送るだけ。位置の最終決定はサーバ。
   クライアント側の即時移動表示は予測として許容し、サーバ値が来たら補正する。

3. **決定論シミュレーション。**
   `Math.random()` は使わず、seed付きPRNG（xorshift128）をワールドに1つ持つ。
   同じseed＋同じ入力列なら同じ結果になるため、テストとリプレイ調査ができる。

4. **状態は1プロセスのメモリが正。**
   SQLiteは「永続化先」であってシミュレーション中の参照先ではない。
   30秒ごと＋island日変わりにスナップショット保存する。

## 4. 実行方法（想定）

```bash
# ルートで
npm install
npm run dev          # server(:8787) と client(:5173) を並列起動
npm run typecheck
npm test
npm run build
```

ルート `package.json` scripts:

```json
{
  "scripts": {
    "dev": "npm run dev --workspaces --if-present",
    "dev:server": "npm run dev -w @ai-pet/server",
    "dev:client": "npm run dev -w @ai-pet/client",
    "typecheck": "tsc -b",
    "test": "vitest run",
    "test:e2e": "playwright test",
    "build": "npm run build -w @ai-pet/shared && npm run build -w @ai-pet/client && npm run build -w @ai-pet/server"
  }
}
```

## 5. 環境変数

サーバのみが読み込みます（リポジトリルートの `.env` を参照）。

| 変数 | 用途 |
|---|---|
| `AZURE_OPENAI_ENDPOINT` | Azure OpenAI エンドポイント |
| `AZURE_OPENAI_API_KEY` | APIキー（**サーバ限定**） |
| `AZURE_OPENAI_API_VERSION` | `2025-04-01-preview` |
| `LLM_MODEL_PET` | `gpt-5.6-luna`（デプロイ名） |
| `PORT` | HTTP/WSポート（既定 8787） |
| `ISLAND_SEED` | 島生成seed（既定 `pokomofu-1`） |
| `DB_PATH` | 既定 `./data/island.db` |
| `LLM_MAX_RPH_PER_PLAYER` | 既定 40 |

Viteには `AZURE_*` を渡さない（`envPrefix` を既定の `VITE_` のまま使い、クライアントは `VITE_WS_URL` のみ参照）。
