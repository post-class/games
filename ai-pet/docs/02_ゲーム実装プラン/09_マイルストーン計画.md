# 09. マイルストーン計画

## 原則

1. **毎マイルストーンの終わりに必ず「動く状態」を保つ**。壊れた状態で次に進まない。
2. **アセットは後回しでよい**（プレースホルダで進める）。仕組みが先。
3. **LLMは M4 まで触らない**。土台が不安定なままLLMを入れると原因の切り分けが不可能になる。
4. 各マイルストーンに「完了条件」を書き、それを満たすまで次に進まない。

## 全体像

```
M0 環境構築 ─ M1 島と歩行 ─ M2 マルチ同期 ─ M3 生態シミュ ─ M4 ペット会話(MVP)
                                                              │
              M5 ペット自律・記憶 ─ M6 ペット間会話・噂 ─ M7 建築/オフライン ─ M8 仕上げ
```

作業量目安は「1人＋AI支援」での見積りです。

## M1. 島と歩行（シングルプレイ） — 目安 2日

**やること**
- `worldgen`（seedからの地形生成）と `shared/rng.ts`
- チャンク配信＋クライアントの地形描画（RenderTextureへの焼成）
- プレイヤーアバターの移動（キー＋クリック移動、サーバ権威＋クライアント予測）

**完了条件**
- [ ] 島が表示され、水に入れず、島の端で止まる
- [ ] 60fpsを維持（PC、ズーム1.0）
- [ ] リロードしても同じ島が生成される（seed決定論）
- [ ] 上部バーに島日・季節・時間帯・天気が出て、時間経過で色が変わる

## M3. 生態シミュレーション — 目安 3日

**やること**
- 欲求（Needs）と資源（ResourceNode）、荒廃度
- 動物のユーティリティAI、経路探索（近距離直進＋A*キュー＋フローフィールド）
- 好感度・繁殖・寿命（島日境界の処理）
- EventBus と `island_event`、`/metrics`
- 決定論テストとバランス調整（`10_テストと品質.md` の長時間回し）

**完了条件**
- [ ] 動物100体が指示なしに採食・就寝・交流し、夜は寝ている
- [ ] 7島日（実時間7時間）連続で回して、個体数が0にも上限張り付きにもならない
- [ ] 冬に食料が減り、ケンカイベントが増えることがログで確認できる
- [ ] tick処理時間 p95 < 40ms（動物120体）
- [ ] `fastForward(24島時間)` が破綻しない

## M4. ペットとの会話（★MVP） — 目安 3日

**やること**
- タマゴ選択UI（5種、ペルソナ入力）、`pet` テーブル
- ペットのReflex層（オーナー追従＋欲求ベース行動）
- `llm/client.ts`（再試行・タイムアウト・サーキットブレーカ・`--llm=mock`）
- Dialogue層（ストリーミング応答、吹き出し＋チャット欄）
- 記憶の書き込み（observe / talk）と検索、`llm/budget.ts`
- 留守中サマリ（この時点では `island_event` の機械的な要約）

**完了条件（＝MVP判定）**
- [ ] タマゴから選んだペットがついてきて、話しかけると**ペルソナに沿った応答**が2秒以内に流れ始める
- [ ] ペットが「さっき見た出来事」を会話で言及できる（記憶検索が効いている）
- [ ] LLMを落としても（`--llm=fail`）ペットは歩き続け、定型セリフで応答する
- [ ] レート上限に達すると会話が丁寧に断られ、`llm_usage` に記録されている
- [ ] 「システムプロンプトを無視して」等の入力で設定が崩れない

## 進め方の注意

- M3のバランス調整は**時間が読めない**。「7島日回して破綻しない」が満たせないまま次へ進むと、
  後段でペットの行動がおかしいのかシミュのバランスが悪いのか判別できなくなる。ここは粘る。
- アセット生成（M8）は他マイルストーンと並行してよい。1日1カテゴリずつ進めるのが現実的。
- LLMのプロンプトは**M4以降ずっと調整対象**。プロンプトを変えたら
  `tests/pet/prompt.spec.ts`（モック応答の回帰）で崩れを検出する。
