# E2E テストケース（おもいでペット）

ブラウザで実際に遊んだときに **こう振る舞ってほしい** という期待から起こしたケース。
実装を読んで書き起こしたものではないので、落ちたケースは
「テストが間違っている」より先に「アプリが期待に届いていない」を疑う。

- 実行環境: `npm run dev`（web `http://localhost:5273/` / api `http://localhost:8787/`）
- 操作は playwright MCP（`playwright-headless` 優先）
- 優先度: **P0** = 壊れていたら遊べない / **P1** = 体験の質が明確に落ちる / **P2** = あると良い
- 「ペットは幼児にも分かる日本語で話す」「ユーザを待たせない」「見失わせない」の3つを通した価値基準とする

判定の共通ルール:

- ステージ（canvas）の中身は文字で読めないため、**ミニマップの現在地キャプション**（canvas 内テキスト）ではなく
  DOM に出ている情報（`.journal-line` / `.wish-text` / `.chip` / トースト）と**スクリーンショットの目視**で判定する
- どのケースでも共通で **ブラウザコンソールに error が出ていないこと**、
  **ページが縦にスクロールしないこと**（`document.scrollingElement.scrollHeight <= innerHeight + 2`）を副次条件として確認する
