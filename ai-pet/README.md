# おもいでペット（ai-pet）

ブラウザで動く 2D・マルチユーザの AI ペット育成ゲーム。
ペットは Azure OpenAI（`gpt-5.6-luna`）でペルソナ化されていて、飼い主のことを覚え、
自分で動き、留守のあいだに他のユーザのペットと出会って話してくる。

調査結果と設計判断は [`01_research.md`](01_research.md) に詳しい。

## この作品の3本柱

### 1. 崩れない性格・忘れない記憶

既存の AI ペットアプリで最も多い不満は「会話が長引くと汎用アシスタント口調に戻る（キャラクター崩壊）」と
「長期記憶の破綻」だった。本作はこれを構造で潰している。

- **性格は 8 軸の数値ベクトル**（元気/甘えん坊/わがまま/賢さ/社交性/食いしん坊/臆病さ/いたずら）。
  毎リクエストで数値から説明文を機械生成して注入するので、履歴が伸びても性格の記述量が薄まらない
  （`shared/personality.ts`）。
- **出力側で崩壊を検出**する。助手口調・メタ発言・箇条書きを検出したら1回だけ言い直させ、
  それでも直らなければ定型に落として、ユーザには崩壊を見せない（`server/llm/speechGuard.ts`）。
- **記憶は3層**（`server/pet/memory.ts`）。
  1. 事実層 — `owner_name` などのホワイトリストされたキーと値。キーで上書きされるので矛盾しない。常に全件注入
  2. エピソード層 — 出来事の要約。`重要度 × 新しさ × 参照実績 + 語の一致` のスコア上位のみ注入。
     ベクトルDBを使わない決定論的な実装なのでテストできる
  3. 直近会話層 — 最新 12 ターン
- **おもいで帳**で、覚えていることを全部ユーザが見て、直して、消せる。
  AI が間違って覚えた記憶をユーザ側から矯正できる点が既存アプリにない。

### 2. ペット同士のAI交流ドラマ

自分がオフラインの間に、ペットが他のユーザのペットと出会って会話する（`server/pet/encounter.ts`）。
双方の性格ベクトルと記憶を入力にするので、相性・喧嘩・仲良しが自然に発生し、関係値が蓄積する。
生成した会話は双方のエピソード記憶に書き戻され、次にログインすると**土産話**として語られる。

「非同期マルチユーザ」と「LLM の強み」が同じ機構で成立するのが本作の核心。

### 3. 自律行動する2Dステージ

ペットは指示待ちではない。ニーズ・性格・時刻から自分で行動を選んで動く。

- 見た目の動きは**決定論的な FSM**（`src/sim/fsm.ts`）で毎フレーム回す。LLM を待たない
- 60〜120 秒に1回だけ LLM に「思いつき」を聞き、行動と独り言を差し込む
- 行動は**ホワイトリスト化された enum**（`shared/actions.ts`）なので、LLM が何を返しても画面は壊れない

## 動かす

```bash
npm install
npm run dev          # サーバ(8787) と Vite(5273) を同時に起動
# http://localhost:5273/
```

リポジトリ直下の `.env` から Azure OpenAI の接続情報を読む（`server/env.ts`）。
**API キーはサーバプロセスだけが読み、ブラウザには一切渡らない。**

| 環境変数 | 用途 |
| --- | --- |
| `AZURE_OPENAI_ENDPOINT` / `AZURE_OPENAI_API_KEY` / `AZURE_OPENAI_API_VERSION` | Azure OpenAI 接続 |
| `LLM_MODEL_PET` | デプロイ名（既定 `gpt-5.6-luna`） |
| `AI_PET_DB` | SQLite の保存先（既定 `data/ai-pet.sqlite`） |
| `AI_PET_PORT` | API サーバのポート（既定 `8787`） |
| `AI_PET_THINK_INTERVAL_MS` | 自律思考の最短間隔（既定 90 秒） |
| `AI_PET_ENCOUNTER_INTERVAL_MS` | ペット同士の交流の最短間隔（既定 3 時間） |

接続情報が無い場合も**遊べる**。LLM が使えないときは定型リアクションにフォールバックする。

```bash
npm run typecheck    # クライアントとサーバの両方
npm test             # vitest（120件）
npm run build
```

## LLM の呼び出し回数（コストの目安）

| 操作 | 呼び出し |
| --- | --- |
| 世話（なでる・ごはん・あそぶ・おてあて）1回 | 1〜2回（崩壊検出でリトライした場合 2回） |
| 会話1往復 | 1〜2回 |
| 自律思考 | 90 秒に最大1回 |
| ペット同士の交流1回 | 1回（やや大きめ、最大 1200 トークン） |

世話は**押した瞬間に定型リアクションを出し**、LLM の一言は返ってきたら差し替える設計なので、
呼び出しが遅くても体感は待たされない（My Talking Tom の手触りを参考にした）。

## 構成

```
shared/       クライアント・サーバ共有（型・性格・行動・アイテム・定型リアクション）
src/          クライアント（Vite + 素のTS + Canvas2D、フレームワークなし）
  render/     ステージ描画（PNG があれば使い、無ければ手続き描画にフォールバック）
  sim/        自律行動 FSM
  ui/         DOM の各パネル（会話・おもいで帳・おへや・ともだち・おみせ）
server/       Express + better-sqlite3（tsx で実行）
  llm/        Azure OpenAI 呼び出し / プロンプト生成 / 応答検証 / 崩壊検出
  pet/        ニーズ・成長・記憶・頭(brain)・交流・留守レポート
public/assets/ img-gen-gpt で生成した透過PNG
10_assets_plan/ アセット生成の台帳（gen.sh / install.py）
tests/        vitest
```

## アセットの再生成

プロンプトはすべて `10_assets_plan/gen.sh` に置いてあり、絵柄を揃えたまま再生成できる。

```bash
bash 10_assets_plan/gen.sh mocha_child_idle      # .tmp/assets/ に出る
uv run --with pillow python 10_assets_plan/install.py   # 整えて public/assets/ へ
```

画像生成には `AZURE_OPENAI_US_*` を持つ `.env` が必要（`AI_PET_IMG_ENV` で差し替え可能）。
`install.py` は、生成画像に残る薄い霞を除いて切り抜き、Web 用に縮小する。

## 遊び方

1. なまえとあいことばで登録し、3種の中から1匹むかえる（性格は種族バイアス込みで1匹ずつ違う）
2. たまごは話せない。世話をして時間が経つと**こども**になり、話し始める
3. 名前や好きなものを話すと覚える。「おもいで」で何を覚えたか確認・修正できる
4. 「ともだち」でほかの人を探し、おへやを見に行ったり、おくりものを送ったりする
5. 「でかけた話」でペット同士の交流ログと土産話を読む
6. 「やくそく」に今日の目標を1つ書いて守ると、ペットが覚えてくれる（コインもたまる）

## 設計上の割り切り

- 認証は個人利用レベル（scrypt + セッションCookie）。公開運用するならレート制限などの強化が必要
- ペットは死なない。放置すると `mood` が下がり会話のトーンが拗ねる方向へ変わる（罰ではなく物語化）
- フレンドは申請・承認なしで相互になる（非同期ソーシャルの摩擦を減らすため）
- ペット同士の交流は LLM 1コールに数秒かかるので、ログイン時に走らせて結果を留守レポートで見せる
