# Multi-Commander

ブラウザで動く 3D 宇宙戦闘ゲーム。往年の名作「ウィングコマンダー」を土台に、
コクピット計器・Nav ポイント・オートパイロット・僚機への通信指示を備える。

## THE VEIL FRONT（十章キャンペーン）

現在の本編は **THE VEIL FRONT**。統合暦 2312 年、ヴェガ宙域。古代の中継門〈ヴェイル〉の
通行権をめぐって**五勢力**（アウレリア連邦／キルラシー帝国／セレシオン遊牧圏／
オルド合議圏／ニューロウム群体）が睨み合い、停戦線だけが残っている。

プレイヤーは空母 TCS タイガーズ・クローの艦載機パイロット。主人公は固定ではなく、
**F-54 専任パイロット5名から選ぶ**（朝倉 澪／神谷 隼人／アミナ・オカフォー／
マーカス・ジョンソン／プロイ・スリスック）。

**勝利は撃墜数では測れない。** 誰を帰し、どの航路を残し、敵に何を約束するかが門の明日を決める。
十章の最後は3つの結末（門の永久閉鎖／限定開放／五者共同管理）に分かれ、どれも解決ではない。
最終無線は勝者の名ではなく、**艦と勢力を問わず帰ってきた者の名前**を読み上げて幕を閉じる。
読み上げられる名前の数だけが、プレイヤーの戦績である。

### 管理する4状態

章末の選択と出撃結果が、次の出撃の「景色」を変える。

| 状態 | 上がる行動 | 下がる行動 | 変わるもの |
| --- | --- | --- | --- |
| 帰還者 | 救難、僚機援護、発砲回避 | 追撃、戦果優先 | 格納庫の会話、僚機の出撃可否、最終無線 |
| 航路信頼 | 中立規約の順守、証拠公開 | 民間損害、協定違反 | セレシオン／オルドの支援内容 |
| 軍令信用 | 命令順守、損害の最小化 | 無許可出撃、内部告発 | 搭載兵装、僚機、司令部の無線 |
| 敵エースの誓約 | 決闘規約の尊重、救難優先 | 撃墜後の侮辱、降伏者の放置 | ラギティカ／ヴァルカーンの協力条件 |

**4状態は出撃結果から動く。** 救助した人数・生存させた護衛対象・僚機の生還/戦死・誤射・民間損害・自機の喪失を
出撃ごとに集計して増減し、デブリーフに `帰還者 +4　+5（救助 3名 / 護衛対象 1隻を生存）　−1（僚機 1名が戦死）` の形で
**理由を1行ずつ**出す。章末の選択は「方針の表明」なので影響を小さくしてある
（同じ状態で 出撃 最大±12 / 選択 最大±5、帰還者は ±6名 / ±2名）。
章末の選択肢そのものも出撃結果で変わる（救助していなければ「救難」は選べず、別の選択肢に差し替わる）。

**実装規約: この4状態は難易度を一切動かさない。** 敵のHP・攻撃力・弾速・命中補正・出現数へは
影響させず、変えるのは味方の顔ぶれ・援護・搭載兵装・無線内容だけである
（状態が低い＝ゲームが難しくなる、ではなく、状態が低い＝孤立して戦う、が正しい）。

### 旧キャンペーン

互換のため、従来の2ルートもタイトルから選べる。

| モード | 内容 |
| --- | --- |
| `veil` | 十章キャンペーン（**新規戦役の既定**） |
| `canon` | 本家寄せ 7章（Enyo 起点） |
| `expanded` | 従来の独自拡張 9章（McCaffrey 起点）。動的作戦つき |

旧2ルートでは、ミッションに失敗してもゲームオーバーにならず、戦況が悪化した「敗北ルート」へ

## 操作方法

マウスだけでも、キーボードだけでも戦闘を完結できる。
マウス操縦は「カーソル位置＝操縦スティックの位置」方式。メニュー操作直後に機首が暴れないよう、
一度カーソルを画面中央付近へ戻すまで操縦入力は無効になる（画面にヒントが出る）。

### 飛行

| 操作 | キー / マウス |
|---|---|
| 機首操縦 (pitch / yaw) | マウス移動（画面中央基準） / ↑↓←→ |
| ロール | Q / E |
| スロットル増減 | `]` `[` / ホイール / `+` `-` |
| スロットル割合指定 | 数字 1〜9 (=10〜90%)、0 で停止 |
| 全速 / 全停止 | `` ` `` / Backspace |
| アフターバーナー（押し続け） | Tab |
| マウス操縦 ON/OFF | M |
| 視点切替（コクピット / 外部） | F |

### 戦闘

| 操作 | キー / マウス |
|---|---|
| 主砲（押し続け） | Space / 左クリック |

## ゲームの流れ

タイトル → ブリーフィング → 出撃 → デブリーフィング → 分岐、を繰り返す。

- **キャンペーン（veil）**: 十章の連続作戦。**分岐で章を増やさず**、勝敗と選択が次章の
  僚機・援護・搭載兵装・無線を変える。敗北しても次章へ進み、達成できなかった勝利条件は
  「記録」として残る（第10章だけは門制御を選べないと成立しないため終端になる）。
  章末に FIELD CHOICE が入り、選んだ結果が4状態へ反映される。
- **キャンペーン（canon / expanded）**: 勝ちルートの各ミッションに対し、失敗すると
  敗北ルートへ分岐し、そこで勝つと本線へ合流する。
- 進捗は localStorage に自動保存され、タイトルの「続きから」で再開できる。
  保存キーは `multi-commander.campaign.v3` のままで、旧セーブもそのまま読める。
- **Nav ポイント**: 各ミッションは Nav を順に巡る。移動は `A` のオートパイロットで、
  近くに敵がいると使えない（＝戦闘を片付けてから進む）。
- **目標種別**: 全滅 / 特定艦の破壊 / 護衛 / Nav 到達 / 一定時間の生存 / 救助 / 偵察 / 制限時間、
  および十章用に追加した **誤射ゼロ / 発砲ゼロ / N隻以上の生存 / N基を秒数維持**、
  さらに **護衛対象を指定 Nav まで送り届ける (`escortArrive`)**。
  `protect` や制限時間のような「制約」は勝利条件に数えず、破られたときだけ効く。
  一方 `escortArrive` は**達成する目標**なので勝利条件に数える
  （「守るだけなら帰投すれば勝ち」にならないようにするための種別）。
  ウェーブ制の増援あり。
- **間合いとタイマー**: Nav に到着したら、その Nav の目標が画面に見える距離（群の中心 2.6km 以内・端 4.8km 以内）へ
  出現位置ごと引き寄せる。移動時間で締切が食われないよう、`timeLimit` は `startAtNav` を指定すると
  **その Nav に到着してから**計時を始める（到着前は「NAV 2 到達後に開始」と出るだけで失敗しない）。
- **達成度**: 任務の結果は **任務達成 / 部分達成 / 任務失敗** の3段階で表示する。
  必須目標を全部満たし、任意目標も残っていなければ「達成」、任意に未達があれば「部分達成」。
  任意目標は `(任意)` ではなく `＋帰還者3` のように**得られるもの**を出す。
  この表記は `MissionRunner.objectiveRewardPrefix()` が唯一の出所で、ブリーフィングと HUD が同じ文字列を読む。
- **救助は自分の手で行う操作**: ポッドや漂流者は近づけば自動で拾えるのではなく、
  **300m 以内へ入り、相対速度 60 m/s 以下まで減速して 3 秒保つ**と収容できる。
  HUD が「接近せよ — 残り ○m」「速すぎる — 減速せよ」「収容中 1.2s / 3.0s」と、何をすれば良いかを出す。
  保持の間は無防備なので、僚機に掩護を頼む意味が生まれる。収容すると搭乗者の名前が出て、
  デブリーフの「連れ帰った者」と第10章の最終無線の読み上げに残る。
- **敵エースとの交渉**: ターゲットがエースのとき、通信メニューの6番が「★ 〈名前〉へ通信」に変わり、
  **名を名乗る / 降伏を勧める / 決闘を申し込む**が選べる。決闘が成立すると相手の陣営の他機は手を出さない。
  撃墜したエースは脱出ポッドを残す。**撃たずに帰せば次の章で再会し**、撃てば二度と現れない。
  座席を撃つ／撃たないは誤射や民間損害には数えず、「敵エースの誓約」だけに効く
  （識別ミスではなく意図的な選択なので、宛先を分けている）。
- **撃つ前に見分ける**: 第2章は「識別」が主題。偽装無人機は **HUD のターゲット名まで騙る**（僚機名・難民船名）が、
  **勢力表示だけは偽装できない**。本物の民間船は照準に収めて2.4km以内を6秒保つと識別が済み（撃つ必要はない）、
  無人機の排除は必須。撃たずに拾って帰るだけでは勝てず、民間船に1発当てれば任務失敗になる。
  誤射したときは「〈艦名〉に命中。識別表示は「中立」——誤射 1発。」と、**なぜ誤射になったか**が無線で読める。
- **戦域離脱**: 戦闘系の必須目標を片付けていれば、敵が残っていてもオートパイロットで帰投できる。
- **脱出**: `Alt+E` を2回押すと機体を捨ててポッドで離脱する。任務は「機体喪失」で失敗するが命は残る。
- **僚機**: `C` の通信メニューから「編隊」「私の目標を攻撃」「散開して交戦」を指示できる。敵の挑発も可能。
- **訓練**: 初回プレイ時のみ、操縦→加速→ターゲット→主砲→ミサイル→オートパイロットを順に案内する。
  ブリーフィング画面で「操作案内なしで出撃」を選べばスキップできる。

## グラフィック

外部アセットを使わず、すべて手続き生成とシェーダ/キャンバスで作っている。

- **艦艇**: 「大きい戦闘機」に見えないよう、段のある厚い船体・等間隔の構造リブ・
  居住区の窓列（一部消灯）・開いた格納庫と照らされた床・甲板の誘導灯・マストとアンテナ・
  2段階のグリーブルを重ねている。**砲塔は最も近い敵を向いて回る**（`RenderSync` が実体に付ける）。
- **陣営の描き分け**: キルラシー機は骨格を連邦と共用しつつ、
  爪・牙・背の肋・赤い単眼を上乗せする（`VisualDef.style: 'kilrathi'`）。
- **機体メッシュ**: 装甲板の継ぎ目、グリーブル (小さな突起)、ガラスのキャノピーと骨組み、
  エンジンナセルと冷却リング、航行灯 (左舷=赤/右舷=緑/尾部=白)、砲身、翼下のミサイルパイロンまで作り込む。
  砲身は `ShipDef.guns` の hardpoint 位置に実際に生えており、弾もそこから出る。
  ジオメトリはマテリアルごとにマージし、`ShipDef` 単位でキャッシュした後 `clone()` で複製するので、
  細部を増やしてもドローコールと生成コストは増えない (`render/PartBuilder.ts`)。
- **3D コクピット内装**: 風防の柱・天蓋の縁・計器盤の筐体・側面コンソール・警告灯を 3D で作り、
  カメラの子として吊る。機体と一緒に揺れ、太陽光が内装を横切る。
  計器そのものは可読性を優先して DOM のまま、この筐体の上に重ねている (`render/Cockpit.ts`)。
- **エンジン噴射**: スロットルとアフターバーナーに応じて伸縮する加算合成のコーン。
  出力が目で分かるので速度感が出る (`render/EnginePlume.ts`)。
- **宇宙塵**: 自機周囲の粒を速度方向の逆へ線分に伸ばす。何も無い空間でも速度が分かる (`render/SpaceDust.ts`)。
- **遠景**: 星3層 (色温度と大きさを分けた点)、多層の星雲 (値ノイズを重ねたキャンバス生成)、
  表面模様・大気・環・衛星を持つ惑星、コロナ付きの太陽、遠方の小天体 (`render/Starfield.ts`)。
- **エフェクト**: 砲口閃光、シールドの金属的スパーク、装甲被弾の火花、
  多段の爆発 (閃光→火球→衝撃波リング→破片→煙)、ミサイル軌跡、
  損傷機から引く煙と火花 (ハル 60% 以下で発生し、損傷が深いほど濃くなる)。
  主砲は武器定義の弾体形状・色・トレーサー長、ミサイルは種類ごとの機体形状・色・誘導軌跡で識別できる。
  HUD には発射不可理由（エネルギー不足 / 砲損傷 / 弾切れ / ロック未完了）と、
  命中確認・撃破・魚雷命中を右上の戦闘ログへ短時間表示する。
- **ポストプロセス**: ACES トーンマッピング + UnrealBloom。
  環境マップ (RoomEnvironment を PMREM で焼いたもの) で金属面が黒く潰れないようにしている。

### 生成画像 (形状は手続き生成、表面は生成テクスチャ)

**形状**はすべて手続き生成のまま。その上で**表面**と UI に生成画像を使っている。
`public/art/` に UI 用の透過 PNG 28枚、`public/art/tex/` に 3D とUI背景用のテクスチャ 35枚
(不透過は JPEG、透過は WebP。合わせて約 7.6MB)。

| テクスチャ | 使う場所 |
|---|---|
| `planet-*` (6種) | Skybox の惑星と、実座標に置くランドマークのガス惑星。ミッションごとに指定 |
| `nebula-*` (4種) | 遠景の星雲スプライト |
| `sun-corona` / `sun-flare` | 太陽の光冠とレンズフレア |
| `rock-*` (3種) | 小惑星の岩肌 (`rock:<変種>` マテリアル、repeat 3) |
| `grime-*` (2種) | 船体の汚れ。陣営別 (`hullGrime` マテリアル) |
| `decal-*` (5種) | 国籍標識・機体番号・注意書き・キルマーク (エースのみ)・キルラシーの爪 |
| `fireball-*` (4種) | 爆発の火球3段階とシールド過負荷の弾け |
| `panel-*` (2種) | コクピット計器盤のラベルと傷 |
| `bg-*` (5種) | タイトル・母艦ハブ・ブリーフィング・格納庫・酒場・自室の背景画 |
| `face-<パイロット>-<表情>` (8人×5) | 通信 VDU・酒場・名簿・追悼のパイロットの顔 |

**パイロットの顔**は、まず基本の顔を1人1枚生成し、その画像を入力にした `edit` で
「同じ人物のまま表情だけを変えた」差分を4枚ずつ作っている (計 8人×5表情)。
喋っている間は「その表情」と「口を開けた顔」を CSS で交互に出して口の動きを作る
(`src/ui/Portrait.ts` の `portraitFace`)。生成画像を持たないパイロットは SVG 版に落ちる。

**テクスチャを貼れる範囲には制約がある。** 手続き生成メッシュの UV は部品ごとに 0..1 なので、
同じ画像を貼ると部品ごとに模様の寸法が変わる。したがって
「汚れ・岩肌」のような**寸法を持たない模様**しか貼れない。
パネル継ぎ目やリベットは今後もジオメトリで作る。
球体 (惑星) は正しい equirectangular UV を持つので、そのまま貼れる。

### UI の紋章類 (生成した透過 PNG)

UI の紋章・勲章・階級章・部屋アイコンは
生成した透過 PNG を `public/art/` に置いて使っている (`src/ui/art.ts`)。

| アセット | 使う場所 |
|---|---|
| `title-crest` | タイトル画面の見出しの上 |
| `emblem-carrier` | 母艦ハブの見出し |
| `emblem-confed` | ブリーフィング / 任務達成 / 授与式 / 勝利エンディング |
| `emblem-kilrathi` | 任務失敗 / 敗北エンディング |
| `patch-squadron` | 追悼画面 / キルボード |
| `medal-*` (8種) | 授与式と自室の勲章棚 |
| `rank-*` (6種) | 階級表示の横 |
| `icon-*` (6種) | ハブのメニュー項目 |
| `radar-bezel` | レーダーの外周の金属ベゼル |
| `dash-trim` | 計器盤の上端を走るリベット付きの梁 |

生成物はそのままでは使えないので、`.tmp/prep_art.py`（UI 紋章）と
`.tmp/prep_tex.py`（テクスチャ）で
「ほぼ透明な色付きノイズの除去 → 外接矩形で切り抜き → 表示サイズへ縮小 →
大きいものは減色」を通してから `public/art/` に書き出している。
円形の部品 (レーダーベゼル) は切り抜き後に正方形へパディングして中心を保つ。
画像が欠けても画面が崩れないよう、読み込み失敗時はその要素を消す。

### 被弾の見え方

何に当たったかが一目で分かるように、3層を描き分けている。

- **シールド**: 六角格子の殻が機体を包んで一瞬光り、当たった面に波紋が広がる (`render/ShieldFx.ts`)
- **装甲・船体**: 橙色の火花と破片が飛ぶ (`Vfx.hitSpark`)
- **蓄積した傷**: 焼け跡と燃える亀裂が船体に残る (`render/BattleDamage.ts`)。
  残ハル 82% から増え始め 20% で最大6箇所。位置は機体ごとに固定なので同じ所が焦げる。
  一度付いた痕は消えない (修理は母艦で行われる＝次の出撃で新品になる)
- **風防**: 反射のすじと拭き残しの汚れが乗り、被弾が深いと**視界の隅に**ひびが入る

## 損傷モデル

被弾は シールド → 装甲（4象限） → 船体 の順に貫通する。船体に通った分から、
**部位が確率的に壊れる**（`sim/subsystems.ts`）。壊れ方は 正常 / 損傷 / 損失 の3段階。

| 部位 | 損傷 | 損失 |
|---|---|---|
| レーダー | 走査線ノイズ・位置がぶれる・一部が映らない | 完全に沈黙 |
| 左舷砲 / 右舷砲 | 40% の確率で不発 | その舷の砲が撃てない（火力半減） |
| エンジン | 最高速 72% | 最高速 40%・AB 使用不可 |
| シールド発生器 | 再生速度 40% | 再生停止 |
| 通信機 | — | 僚機へ指示できない |
| 姿勢制御 | 旋回 75% | 旋回 45% |

### 被弾の段階と撃墜

被弾は **シールド健全 → シールド喪失 → 装甲被弾 → 船体被弾 → ハル危険域** の5段階で読ませる
（判定は `hud/damageStage.ts` が唯一の出所。HUD・音・無線がすべてここを読む）。
段階が進んだ瞬間だけ、画面上部に「何が起きたか／どうするか」を1回出し、段階ごとに違う音を鳴らす。
ハルが 30% 以下になると画面周辺が赤く縁取られ、低い連続警報と
**「ハル危険域 — Alt+E で脱出できる」**が出る（`reducedFlashes` では脈動を止め、文字と音は残す）。

**僚機と護衛対象にも同じ段階を適用する。** 被弾すると本人が無線を入れ、
失われたときは画面中央に `Sable 戦死` / `〈アストラ・メイ〉 喪失` を数秒出す（右上の撃墜ログとは別枠）。
固有名は `SpawnGroupDef.displayName` が唯一の出所で、`MissionRunner.displayNameOf()` から読む。

**自機が撃墜されたら即暗転しない。** 約 4.2 秒、機外視点で爆発を見せ、管制の無線が入るまで待つ。
その間の入力は破棄するので、間が明けた直後に操作が暴発しない。
任務が失敗で終わるときも見出しを読める時間（約 3.6 秒）を確保する。

**被弾面で壊れる部位が偏る**。左から撃たれれば左舷砲、後ろからならエンジン、正面ならレーダーが壊れやすい。
壊れた機体で深追いするか帰投するかの判断がプレイに入ってくる。
故障率は難易度で変わる（やさしい 0.35 / ふつう 0.7 / むずかしい 1.15 倍）。

## コクピット計器

コクピット表示（風防の柱・天蓋の縁・計器盤の筐体）は **既定で ON**。
黒帯で視界を狭めるのではなく実際の構造物で四隅を締め、**画面中央 60% は必ず抜けている**
（`render/Cockpit.ts` の `COCKPIT_OPENING`。侵入しないことを単体テストで固定している）。
設定の「コクピット表示 (風防・計器盤)」で切れる。

**構造物に隠れている対象には枠を付けない。** 風防の開口部の外へ投影されたターゲット枠・ラベル・
ITTS リードは描かず、開口部の縁に方向矢印だけを出す（見えないものに「ここにいる」と書かないため）。
照準環は画面のちょうど中央に置く。コクピット視点のカメラは機体の姿勢そのままなので、射線は中央に投影される。

`F` の外部視点では DOM の計器盤を隠し、速度・スロットル・ターゲット・Nav・目標だけの最小 HUD に置き換える。

画面下部のダッシュボードに以下を表示する。

- **左 VDU**: ターゲット情報（パイロット名 / 機種 / 距離 / 接近率 / シールド / ハル）
- **中央**: 速度、スロットル、砲エネルギー、AB 燃料、シールド/アーマー図（前後シールド＋4象限装甲＋ハル）、レーダー
- **右 VDU**: 武装と残弾・ロック状態（`D` で被害状況に切替）
- **右 VDU の武器欄**: `X` で選択中の副兵装を切り替え、武器名・用途・残弾・砲エネルギー・
  ロック進行を確認できる。無誘導弾は「ロック不要」、誘導弾は進行率と「ロック未完了」も表示する。
- **上部オーバーレイ**: 照準環、ITTS リードレティクル（黄色の点線＝そこを撃てば当たる位置）、
  ターゲット枠、画面外ターゲット/Nav の方向矢印、無線ログ、撃墜ログ、命中通知、任務目標、各種警報

レーダーは球面レーダー。中心が機首方向、外周が真後ろ。赤＝敵、青＝味方、金＝エース、白＝ミサイル、
灰＝小惑星、橙＝機雷（障害物は 3 km 以内のみ、機体の枠を潰さないよう別枠で 6 個まで）。

## 音と演出

音源ファイルを持たず、すべて Web Audio の合成で鳴らす。

- **BGM**: 音符として書き下した譜面（`audio/score.ts`）を AudioContext のクロックで先読みスケジュールする。
  4系統 — **主題**（タイトル・母艦ハブ）/ **戦闘**（戦域）/ **勝利**（任務達成・叙勲）/ **追悼**（任務失敗・戦死者）。
  戦闘曲は主題を刻みに崩したもの、追悼は主題を引き伸ばしたものなので、同じ旋律として繋がって聞こえる。
  戦闘曲は近くの敵の数に応じて層（低音の刻み → 主旋律 → 裏打ち → 高音の警笛）とテンポが増える。
  曲の切り替えはクロスフェードする。
- **無線の声**: 実音声の代わりに、帯域を絞ったパルス列で音節の輪郭だけを作る。
  話者名から基本周波数を決めるので同じ人物は同じ声になり、口調で抑揚の向きが変わる。
  前後に無線のスケルチが入り、喋っている秒数を HUD へ返して顔の口を開閉させる。
- **武器と戦闘音**: レーザー / マスドライバー / ニュートロンガン / パーティクルキャノンは
  発射音の音域・ノイズ量・減衰を変え、ミサイルは種類別の発射音を使う。シールド命中・装甲命中・
  船体命中、ロック完了、爆発も別イベントとして発音し、同じ音の連射はスロットリングする。
- **ジャンプ演出**: オートパイロット中は宇宙塵を長い筋に伸ばし、視野角を広げ、発光を強める。
  開始で上昇し終了で下降するスイープ音が付く。
- **撃墜演出**: エースを自分で落としたとき、または艦艇が沈むときだけ、
  時間を 0.38 倍に落として爆発の方へ視線を寄せる。全部の撃墜でやると忙しくて読めないので山場だけに限る。

## 手動確認

`npm run dev` で起動し、ブリーフィングから任務へ出撃する。次の順で、画面下の右 VDU と右上ログを確認する。

1. `X` でダムファイア、誘導ミサイル、魚雷を切り替え、武器名・用途・残弾・エネルギーを確認する。
2. 誘導ミサイルまたは魚雷を選び、ターゲットを `T` / `R` / `Y` で指定する。正面を向いている間にロック率が増え、
   完了前に `Enter`（または右クリック）を押すと「発射不可 — ロック未完了」と出る。
3. ミサイルを撃ち切って「発射不可 — 弾切れ」を確認する。主砲は `Space`（または左クリック）を保持し、
   エネルギーを使い切ると「発射不可 — エネルギー不足」、被弾で砲が損傷すると損傷表示を確認する。
4. 敵へ主砲・ミサイルを命中させ、右上に「命中確認」、撃破時に「撃破」を確認する。艦艇へロックして魚雷を命中させると
   「魚雷命中」が出る。
5. `D` で被害表示へ切り替え、`reducedFlashes` や音量設定を変えた場合も文字情報が残ることを確認する。

自動確認は次を実行する。

```bash
npm run typecheck
npm test
npm run build
```

## 既知の制限

- 命中イベントの武器ID・命中面・距離は新しい発射物イベントで提供されるが、障害物や衝突など古い経路では未指定になる。
  その場合も描画・音声は汎用の命中表現へ安全にフォールバックする。
  魚雷命中ログは爆発中心・爆風半径・対象数を使うため、同時爆発時は表示が間引かれる場合がある。
- 砲損傷は左右砲の状態を表示するが、損傷状態の不発判定は確率的なので、表示が「火力低下」のときも片側だけ発射できる場合がある。
- Web Audio はブラウザの自動再生制限に従う。最初のクリックまたはキー入力までは音が鳴らず、低スペック環境や大量交戦ではエフェクト・音が間引かれる。

設計上のポイント:

- **ロジックと描画の分離**: `sim/` は Three.js のシーングラフを知らない。
  `render/RenderSync` が Entity を Object3D に反映するだけなので、シミュレーションを Node 上でテストできる。
- **汎用 ECS は作らない**: `Entity` は optional フィールドを持つ素の構造体。
  システムは「配列を受けて更新する関数」。追いやすさとテスト容易性を優先した。
- **固定dt物理 + 可変dt描画**: 60Hz 固定でシミュレーションし、描画は残り時間で補間する。
  フレームレートによって挙動が変わらない。
- **操縦入力の共通化**: プレイヤー・AI・僚機はすべて同じ `ThrusterInput` を出力し、飛行モデルは区別しない。
- **手続き生成アセット**: 機体は Three.js のジオメトリ合成で生成する（外部アセット不要）。
  `ShipDef.visual.gltf` を指定すると非同期で GLTF に差し替え、ロード失敗・空モデル・消滅時は
  手続き生成へ安全にフォールバックする。
- **音の役割分担**: 効果音と無線の声は Web Audio のオシレータ/ノイズから合成し、
  BGM は `public/audio/music/` の MP3 を状況に応じてクロスフェードする。
- **陣営は五勢力**: `Faction` は `confed` / `kilrathi` / `serecion` / `ordo` / `neurowm` / `neutral`。
  敵対関係は「a !== b」ではなく**敵対ペアの表**で定義し、`setFactionStance()` で出撃中だけ
  組み替えられる（第8章の停戦、第10章の共同作戦）。復帰は `MissionRunner.dispose()` が
  宣言の有無に関わらず必ず行うので、他ミッションへ漏れない。
  なお実装idのキルラシーは `kilrathi`（th）で固定し、設定資料の表記 `kilrashi`（sh）との差異は
  `veil/world.ts` の `FACTION_ID_MAP` に集約している。
- **表示文の単一の出所**: 勢力名・戦域名・人物名・章の本文は `veil/` のデータだけが持つ。
  無線の話者名は `speakerName()` を必ず通す（名簿の `William Hart（ウィリアム・ハート）` を
  表示用に整形する。この整形を各所で再実装して表記が崩れた経緯がある）。

## 難易度

| | 敵技量 | 被ダメ | 与ダメ | 同時攻撃 | ウェーブ遅延 |
|---|---|---|---|---|---|
| やさしい | 30% | ×0.55 | ×1.35 | 1機 | +12秒 |
| ふつう | 58% | ×1.0 | ×1.0 | 2機 | +4秒 |
| むずかしい | 80% | ×1.2 | ×0.9 | 3機 | +0秒 |

このほか、難易度で アフターバーナー燃料（×1.6 / ×1.0 / ×0.85）、
部位故障の発生率（×0.35 / ×0.7 / ×1.15）、照準アシストの強さ（1.0 / 0.45 / 0.45）が変わる。

AI の命中精度は「技量 × 距離」で決まる。遠距離の撃ち合いはほぼ当たらず、接近戦で初めて削り合いになる。
このため、照準の上手いプレイヤーが戦局を決める役割を担う（同技量の AI 同士は決着しにくい）。

自動プレイ（AI に自機を操縦させる通しテスト）での確認結果:

- やさしい: 平凡な腕（技量 0.7 相当）でも全6ミッションを完走できる
- ふつう: 上手い腕（技量 0.88 相当）で第5章まで到達。最終ミッション（旗艦攻撃）は
  自動プレイでは突破できていない（魚雷ランは AI が苦手とする操作なので、実プレイでの確認が必要）
- むずかしい: 第3ミッションで撃墜される
