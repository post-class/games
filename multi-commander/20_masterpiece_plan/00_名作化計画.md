# multi-commander 名作化計画

作成: 2026-08-03

## 0. この文書の位置づけ

`10_next_constructions/00_ウィングコマンダー超えのためにやること.md`（以下「機能表」）は
**WC に追いつき、超えるための機能リスト**である。現在 34/69 が完了している。

本書は別の問いを扱う。

> 機能表を全部埋めたら名作になるのか。

> 実装ステータス（2026-08-05）: コードで検証可能な実装項目は完了し、下記のチェックを更新した。固定ステップのリプレイ再生（コクピット／追尾／戦術視点）も実装済み。
> 人間による通しプレイ・実聴・実機の入力遅延測定・主観評価は、エージェントが代行できないため未確認のまま残す。

ならない。機能表を全部埋めても「WC の全機能を持つ習作」で終わる可能性が高い。
名作と習作を分けるのは機能の数ではなく、**手触りの精度**と**プレイヤーの記憶に何が残るか**である。
本書はそこを計画する。

## 1. まず背骨を1行に決める

機能を足す前に、**何の game なのか**を1行で決める。これが無いと機能表は「WC にあった物リスト」に
退化し、豪華だが芯の無いものになる。

> **連れて行った者を、連れて帰れるか。**

- プレイヤーは英雄ではなく、飛行隊の1機である。
- 撃墜数は目的ではない。**帰投したときに誰が隣にいるか**が結果である。
- 戦争には勝てない。宙域を守れるかどうかだけが決まる。

この1行を判断基準として使う。**新機能はこの1行に奉仕するか**で採否を決める。

| 機能 | 背骨への奉仕 | 判定 |
|---|---|---|
| 宿敵（逃がした敵エースの再登場） | 「連れて帰れなかった」記憶に顔が付く | ◎ 最優先 |
| 補給の有限性 | 護衛失敗が次の任務を苦しくする＝連れて帰る難度が上がる | ◎ |
| 飛行隊の編成管理 | 誰を連れて行くかがプレイヤーの判断になる | ◎ |
| 訓練室 | 腕を上げれば連れて帰れる。学習の場 | ○ |
| リプレイ | 「あの一撃」を見返す。記憶の外部化 | ○ |
| 統計画面 | 数字は記憶にならない。あくまで補助 | △ |
| 対戦マルチプレイ | 背骨に無関係。別のゲームになる | × 切る |
| ミッションエディタ | 作る人の道具。プレイヤー体験ではない | × 後回し |

## 2. 名作の条件を分解して現状を採点する

主観だが、書いておかないと議論できない。**× と △ が名作化の作業対象**である。

| # | 条件 | 現状 | 評価 | 根拠 |
|---|---|---|---|---|
| A | **手触り** — 撃つ・当たる・曲がるが気持ちいい | キーボード＋マウスのみ。命中フィードバックは音とヒットストップ | △ | スティックが無い。空間戦闘の最良の入力を欠いている |
| B | **公平性** — 死んだ理由が必ず分かる | 障害物警告と部位損傷の表示は入れた | △ | **人間が一度も通しプレイしていない**（後述の最大リスク） |
| C | **学習曲線** — 教えられずに上手くなる | 6段の訓練シーケンスのみ | △ | 訓練室が無く、失敗から学ぶ場が本番しかない |
| D | **記憶に残る出来事** — 語れる瞬間が生まれる | パーマデスと追悼、エース撃墜のスロー | ○ | 敵側に人格が無い。倒す相手が匿名 |
| E | **世界が動いている感覚** — 自分の戦果が world を変える | 固定の分岐グラフ（9章＋敗北2） | × | 勝っても負けても同じ番号のミッションが来る |
| F | **反復に耐える** — もう一度飛びたくなる | 11 ミッション、通し1回で終わる | × | 手続き生成も challenge も無い |
| G | **誰でも遊べる** — 入力・視覚・酔いへの配慮 | 難易度3段、無線表示時間、照準アシスト | △ | キー再割り当て・色覚・画面揺れ抑制が無い |
| H | **壊れない** — セーブ破損・詰み・クラッシュが無い | 114 テスト、詰み1件は修正済み | ○ | セーブのバージョン移行が未整備 |
| I | **見た目** — 手続き生成でどこまで押せるか | 機体・艦艇の作り込み、砲塔追従、陣営の描き分け、被弾痕、風防、**生成テクスチャ35枚** | ◎ | 艦艇のデカールとパイロットの顔が残る |
| J | **音** — 覚えて帰れる | 旋律を持つ4系統、無線の声の代替 | ○ | **一度も人間が聴いていない**（ヘッドレス検証のみ） |

## 3. 第I期: 名作の前提条件（これを飛ばして先へ行かない）

### 3-1. 人間による通しプレイ検証 ★最大のリスク

**現状の問題**: バランスは自機に AI を載せた自動プレイでしか測っていない。
これは「AI が得意なこと（正確な偏差射撃）」に最適化され、
「人間が苦手なこと（3次元での姿勢把握、複数機の同時監視）」を見落とす。
音も一度も聴いていない。**今のバランスは根拠が弱い、と明示しておく。**

- [ ] 難易度「ふつう」で勝ちルート9ミッションを人間が通しプレイし、各ミッションで記録する
  - 死んだ回数と、死んだ直後に「理由が分かったか」（分からなければ B の欠陥）
  - 詰まった箇所と、その理由（操作が分からない / 難しすぎる / 目標が不明）
  - 手が疲れる操作、目が疲れる演出
- [ ] BGM 4系統を実際に聴き、音量バランスと音色を調整する
  （層ごとの `gain` / `cutoff` は `audio/score.ts` の1箇所で直せる）
- [ ] 無線の声（`AudioManager.radioVoice`）が「喋っている」に聞こえるか確認する。
  聞こえなければ音節長・帯域・抑揚を調整、それでも駄目なら**廃止して無音＋口の動きだけにする**
- [ ] 記録をもとに難易度3段のパラメータを引き直す（`app/settings.ts` の `DIFFICULTIES`）

**受け入れ基準**: 初見の人間が「ふつう」で第3章まで到達でき、死因を毎回説明できる。

### 3-2. 手触りの磨き込み

名作の 9 割は手触りである。ここは機能追加ではなく**精度**の作業。

- [x] **ゲームパッド対応** — 左スティックで機首、トリガーで射撃、L/R でロール、
  アナログのスロットル軸。デッドゾーンと感度カーブを設定に出す
- [x] **キー再割り当て** — `InputManager` の対応表を設定から差し替えられるようにし、
  localStorage に保存する
- [x] **命中の手応えを層で作る** — 現在は音とヒットストップのみ。
  シールド命中（弾ける）／装甲命中（削れる）／ハル命中（内部が抜ける）で
  音・火花・カメラの反応を明確に描き分ける。**当てた瞬間に何に当たったか分かる**状態にする
- [x] **カメラの追従を調整する** — 旋回時の遅れ、AB 時の画角、被弾時の揺れの強さを
  すべて設定で 0 にできるようにしつつ、既定値を気持ちいい所に置く
- [ ] **入力遅延の実測** — 押してから弾が出るまでを計測し、1フレーム分の無駄があれば潰す
  （ゲームパッドのサンプリングは固定ステップ化済み。実機での遅延計測は未実施）

**受け入れ基準**: スティックで 5 分飛んで、キーボードに戻りたくならない。

### 3-3. 宿敵システム（記憶に残る出来事の核）

背骨に最も効く未実装機能。**倒す相手に顔を付ける**。

- [x] 敵エースを永続化する（`content/aces.ts` を新設し、セーブに状態を持つ）
  - 逃がしたエースは名前・機体・撃墜数を覚えて後のミッションに再登場する
  - 再登場のたびに技量が上がり、機体が更新される
  - こちらの僚機を落としたエースは**その僚機の名前を無線で言う**
- [x] エースとの遭遇に専用の演出を入れる — 固有の無線、BGM の切り替え（第5系統「宿敵」）
- [x] 撃墜すればキルボードと戦績に永久に残る。逃がせば酒場で噂になる
- [x] エースは撤退を判断する（士気システムを流用）。**倒し切れないことがある**のが重要

**受け入れ基準**: プレイヤーが敵パイロットの名前を口にする。

## 4. 第II期: 名作の骨格（世界が動く）

### 4-1. 動的キャンペーン（条件 E への回答）

固定の分岐グラフを捨て、**戦況テーブル**を置く。

- [x] `content/frontline.ts` — 星系ごとに制宙度・敵戦力・補給線の3値を持たせる
- [x] ミッション結果が戦況を動かす。護衛成功は補給線を守り、敵艦撃沈は敵戦力を削る
- [x] 戦況から次のミッションを選ぶ（テンプレート＋戦況の組み合わせで生成）
- [x] 星系マップ画面で戦線を可視化する。**押している/押されているが目で分かる**
- [x] 中間結末を用意する — 完全勝利 / 辛勝（宙域は守ったが飛行隊は壊滅）/
  痛み分け（撤退したが艦は残った）/ 敗北

### 4-2. 補給の有限性（因果の可視化）

- [x] ミサイル・フレアを母艦の在庫から出す。護衛失敗で在庫が減る
- [x] 格納庫で「今日は魚雷が2本しかない」状態が起きる
- [x] 在庫が尽きると機体の選択肢が狭まる

### 4-3. 飛行隊シミュレーション

- [x] プレイヤーは1機でありつつ、**誰を何番機に置くか**を決める
- [x] 隊員同士の関係（Maniac と Angel は仲が悪い、など）が編隊の挙動に出る
- [x] 隊員が昇進し、やがて別の隊へ移る。新人が来る
- [x] 全員死ぬと飛行隊が解隊される（＝敗北条件の1つ）

### 4-4. ミッションの量と種別

- [x] 20 前後まで増やす（固定20任務。動的作戦はさらに生成）。ただし**量より配置**
- [x] 「何も起きない哨戒」を1つ入れる。起きない任務が混じるから起きたときが怖い
- [x] キャピタルシップ強襲の多段構成（砲塔 → エンジン → 魚雷）
  ※ 艦艇に部位損傷を拡張する必要がある（`sim/subsystems.ts` は現在戦闘機のみ）

### 4-5. 反復に耐える構造（条件 F への回答）

- [x] **訓練室** — 母艦から入れる。敵の種類・数・技量を自由に設定して練習できる
- [x] **リプレイ / キルカム** — 直近30秒を保存し、任意の視点から見返せる
  （固定 dt シミュレーションなので入力列を記録すれば決定論的に再生できる。
  `core/rng.ts` に seed 記録を足すだけで実現可能）
- [x] **統計** — 命中率、平均交戦時間、機体別戦績、最も長く生き残った僚機

## 5. 第III期: 名作の表面（磨き上げ）

### 5-1. 描画

**優先を繰り上げて着手中** (ユーザー指示: 見た目のリッチさが最優先)

- [x] **砲塔の追従動作** — 艦艇の砲塔をテンプレートから外し、`RenderSync` が砲門ごとに実体を生やして
  最も近い敵へ向ける。待機時は舷側の外を向いて揃う
- [x] **艦艇の巨大さ** — 段のある厚い船体、等間隔の構造リブ13本、居住区の窓を3列（一部消灯）、
  開いた格納庫と照らされた床、甲板の誘導灯、マスト・皿・アンテナ、2段階のグリーブル
- [x] **発光の整理** — 甲板灯に `lamp` マテリアル（控えめな自発光）を新設。
  全白 `MeshBasicMaterial` + 低いブルームしきい値が原因で、日向の金属面と灯火が
  レーザーのような白い棒に潰れていたのを解消（しきい値 0.82 → 0.93、強度 0.62 → 0.52、
  accent と metal の反射を落とす）
- [x] **影側の可読性** — 影側が真っ黒で形が読めなかったので補助光を 0.5 → 0.8、環境光を 0.8 → 1.0
- [x] **被弾痕** — `render/BattleDamage.ts`。実体ごとに焼け跡（黒い染み）と燃える亀裂（加算合成）を
  船体表面へ貼る。残ハル 82% から増え始め 20% で最大6箇所。位置は実体 id を種にした固定乱数なので
  同じ機体では同じ場所が焦げる。一度付いた痕は消えない（修理は母艦で行われる＝次の出撃で新品になる）
- [x] **シールドの被弾表現** — `render/ShieldFx.ts`。六角格子のテクスチャを張った殻が一瞬光り、
  当たった面に波紋が広がる。火花だけでは「何に当たったか」が分からないので、
  装甲・船体への命中（`Vfx.hitSpark`）と明確に描き分ける
- [x] **キルラシー側の描き分け** — `VisualDef.style: 'kilrathi'` で爪・牙・背の肋・赤い単眼を上乗せ
- [x] **コクピットのガラス** — 上端から差す反射のすじ・拭き残しの汚れ・被弾で入るひびを
  加算合成の薄板で重ねる。ひびは**視界の中央を避けて隅に小さく**入れる
  （大きく入れると弾も敵も見えなくなり、被弾が「見えない」罰になってしまう）
- [x] **表面に生成テクスチャを入れる** — 惑星6種・星雲4種・太陽・岩肌3種・船体の汚れ2種・
  デカール5種・爆発4種・計器盤2種・UI 背景5種（計35枚、約7MB）。
  詳細と判断の記録は [`01_グラフィック強化リスト.md`](01_グラフィック強化リスト.md)
- [ ] GLTF 差替（`ShipDef.visual.gltf` は用意済み）は**最後**。手続き生成で足りている

### 5-2. 音

- [x] キャラクターごとのライトモチーフ（宿敵、僚機の死、母艦）
- [x] 適応ミックス — 交戦中は BGM を下げて無線を通す
- [x] エンジン音を機体ごとに変える

### 5-3. アクセシビリティ（条件 G への回答）

- [x] 色覚多様性 — 敵味方を色だけでなく形状（△/○）で冗長化
- [x] 画面揺れ・明滅・ブルームの抑制オプション
- [x] 操作補助の段階 — 自動水平、旋回補助、時間減速
- [x] 字幕サイズと表示時間

### 5-4. 壊れないこと（条件 H への回答）

- [x] セーブのバージョン移行（`v2` から `v3` へ移行し、新規フィールドを既定値で補完）
- [x] 性能予算を決める — 60fps を維持する敵機数の上限を実測し、超えたら描画を落とす
- [x] エラー境界 — 例外でゲームが白画面にならないようにする

## 6. やらないこと（スコープ規律）

名作にならない原因の多くは、やらないことを決めないことである。

| やらない | 理由 |
|---|---|
| マルチプレイ（協力・対戦） | 背骨（連れて帰る）に無関係。通信層の実装コストが全機能中最大 |
| ミッションエディタ | プレイヤー体験ではなく作者の道具 |
| モバイル対応 | 入力が根本的に合わない。手触り（条件 A）を犠牲にする |
| 実写ムービー / 音声収録 | 合成音と SVG の顔で代替済み。ここに投資すると他が止まる |
| 3D モデルの外注・GLTF 化 | 手続き生成が破綻していない。破綻してから考える |
| 独自エンジン化・ECS 再導入 | 現在の素の構造体＋関数で 15,000 行が読める状態を維持する |

## 7. 工程

各期の終わりで**必ず遊べる状態**にする。期をまたいだ作りかけを残さない。

| 期 | 内容 | 目安 | 完了条件 |
|---|---|---|---|
| **I** | 人間検証 → 手触り → 宿敵 | 全体の 30% | 初見が「ふつう」で第3章まで行き、敵エースの名前を覚える |
| **II** | 動的キャンペーン / 補給 / 飛行隊 / 訓練室・リプレイ | 全体の 45% | 2周目のプレイが1周目と違う展開になる |
| **III** | 描画・音・アクセシビリティ・堅牢性 | 全体の 25% | 設定画面だけで遊びやすさを調整でき、白画面が出ない |

**順序の理由**: I を先にやる。手触りが悪いまま機能を積むと、
後で手触りを直したときに全ての機能のバランスを引き直すことになる。
III を最後にする。見た目と音は最後に足しても効くが、手触りと構造は後から差し替えられない。

## 8. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **AI 自動プレイだけでバランスを決めている** | 人間には理不尽、または退屈になる | 第I期の最初に人間検証。以後、難易度を触るたびに人間で確認する |
| **音を聴かずに作っている** | 音量が破綻、音色が不快 | 第I期で実聴。駄目なら廃止も選択肢に入れる（無音は不快音より良い） |
| 動的キャンペーンで物語が薄くなる | 手続き生成の任務は無個性になりやすい | 骨格は動的、**節目だけは手書きミッション**を固定で挟む |
| 機能を足すほど 15,000 行が読めなくなる | 変更速度が落ちる | `sim/` の Three.js 非依存を死守する。テストは機能追加と同時に書く |
| 宿敵システムが「強い敵が出るだけ」になる | 記憶に残らない | 台詞で必ず**過去の出来事に言及**させる（誰を落としたか、どこで逃げたか） |
| スコープが膨らんで完成しない | 最悪の結末 | §6 の「やらないこと」を守る。機能表の残り35項目も §1 の表で再選別する |

## 9. 名作かどうかの測り方

実装量ではなく、**プレイヤーの口から出る言葉**で測る。機能表の §5 を引き継ぎ、拡張する。

- [ ] 僚機の名前を、プレイヤーが自分から口にするか（例: 「Spirit が落ちた」）
- [ ] **敵パイロットの名前を口にするか**（宿敵システムの成否）
- [ ] 損傷して帰投するとき、手に汗をかくか
- [ ] ミッション間に寄り道したくなるか（酒場に行く理由があるか）
- [ ] 負けた後に、続けたくなるか（敗北が罰ではなく物語になっているか）
- [ ] 同じ戦域をもう一度飛びたくなるか（動的キャンペーンの成否）
- [ ] BGM を口ずさめるか
- [ ] **死んだとき、自分のミスだと思えるか**（理不尽だと思ったら公平性の欠陥）
- [ ] **誰かに話したくなる出来事が、1周のうちに1つ以上起きるか**

最後の項目が本命である。**語れる出来事が起きない game は、機能が揃っていても名作にはならない。**
