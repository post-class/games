### 想定から変えた点

- **A2 を equirectangular 1枚 → スプライト4枚に変更した。**
  全天1枚は継ぎ目が必ず1本出る。既存の星雲スプライト機構にテクスチャを差し替える方式なら
  継ぎ目が無く、実装も1行で済む。タイトル画面用の広い絵だけ別に `bg-space` を作った。
- **C3 の VDU 枠は採用しなかった。**
  実機で見ると枠の内側の発光が「TARGET」「WEAPONS」のラベルを隠した。
  装飾より文字の可読性を優先し、枠を外して警告灯の列だけを計器盤の梁に載せた。
  生成した `hud-vdu-frame.webp` は残してあるが未使用。
- **C5 パイロットの顔は生成画像に置き換えた（口の動きも維持）。**
  「表情差分と口の動きを失う」という懸念は、`edit` で**同一人物の表情差分**を作れたことで解消した。
  基本の顔を1人1枚生成し、それを入力に「口を開けた talk / 苦痛 / 得意 / 沈痛」の4枚を作り、
  喋っている間は「表情」と「口を開けた顔」を CSS で交互に出す。
  `input_fidelity: high` は gpt-image-1-mini では使えないので、**編集だけ gpt-image-2** を使った。

### 実装中に直したもの

- 汚れテクスチャは `map` として乗算されるため船体が一律に暗くなった。
  `lighten(hull, 1.6)` で船体色を持ち上げて元の色味を保つようにした。
- デカールの寸法を「高さ×縦横比」で決めていなかったため、機体番号が機体より大きく描かれていた。
  `size` を高さの意味に統一し、幅は `aspect` を掛けて求める形にした。
- ランドマークのガス惑星が円筒を重ねた縞模様のままで、Skybox の惑星と質が揃っていなかった。
  こちらにも生成テクスチャを貼り、縞の円筒を廃止した。

## 1. 技術的な前提（先に確認した事実）

生成画像を 3D に貼れるかは UV の有無で決まる。実機で確認した。

- **マージ後のジオメトリに UV は残っている**（機体・岩ともに `attributes.uv` あり）
- ただし UV は**プリミティブごとに 0..1**。`PartBuilder` は BoxGeometry 等をスケールして合成するので、
  同じテクスチャを貼ると**部品ごとに模様の大きさが変わる**。
  → **パネル継ぎ目のような「寸法のある模様」は破綻する。**
  → **汚れ・摩耗・岩肌のような「寸法を持たない模様」なら成立する。**
- 現在のテクスチャ数は 32、ジオメトリ 81。テクスチャを増やす余地は十分ある。
- 球体 (`SphereGeometry`) は正しい equirectangular UV を持つので、
  **惑星と背景球は生成画像をそのまま貼れる**（最も費用対効果が高い）。

## 3. やらない／保留

| 項目 | 理由 |
|---|---|
| パネル継ぎ目・リベットの詳細テクスチャ | UV が部品ごと 0..1 なので寸法が破綻する。継ぎ目は**ジオメトリで作る**方が正しい（既に実装済み） |
| ノーマルマップ / ラフネスマップ | 生成画像から正しい法線は作れない。輝度から擬似生成すると破綿しやすい |
| 機体の完全な UV アンラップ | 手続き生成の設計と相反する。GLTF に移行する時の話 |
| 6面スカイボックス | 継ぎ目が6箇所出る。equirectangular 1枚（A2）で足りる |

`.tmp/prep_art.py` に変換と圧縮の段を足して、透過が要らないものは JPEG にする。

## 6. 方針変更の明記

当初の制約は「手続き生成のみ・外部アセットDLなし」だった。
UI の紋章 (28枚) で既にこれを緩めているが、上の計画は**3D の表面にも生成画像を入れる**ので、
「手続き生成でジオメトリを作り、表面は生成テクスチャで質を上げる」という方針に変える。
GLTF による**形状**の置き換えは引き続き最後（計画書 §5-1）。
