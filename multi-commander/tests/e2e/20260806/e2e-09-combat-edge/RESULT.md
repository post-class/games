# E2E-09 戦闘エッジ追加確認

結果: PASS（画面・操作経路・ポーズ画面の視覚表示を確認）

実施方式: Playwright headless MCP / `http://127.0.0.1:4173/`

## 実施済み

- 非quietの`patrol`訓練を開始し、戦闘開始直後の画面を確認。
- キーボード: 矢印4方向、Q/E、`[`/`]`、`+`/`-`、数字0〜9、`` ` ``、Backspace、Tab、M/F/X/G/T/R/Y/D/C/N/A、Space、Enterを入力。
- 主砲・右クリックによるミサイル発射、ホイール、マウス移動、左クリック、右クリックを操作。弾数減少・HUD更新を確認。
- `N`で航法マップ、`C`で通信メニュー、`D`で被害表示を確認。`navigator.getGamepads()`はAPI有り・接続0件。
- viewportを`420x720`へ縮小して表示を確認し、通常サイズへ復帰。
- Escでポーズを確認。ポーズ画面の「再開／設定／操作方法／リプレイ／やり直し／タイトルへ戻る」を確認できる状態を保存。
- Alt+E 1回目の「もう一度 Alt+E で脱出する」を確認。
- Alt+E 2回目で「訓練中断」デブリーフへ到達。
- Raptorへ切り替え、誘導兵器のロック未完了→ロック完了→Enter発射を確認。
- 敵の交戦によりシールド低下、装甲／船体損傷、右舷砲損傷、撃墜による訓練中断を確認。
- ダムファイアを使い切り、弾薬0と「発射不可 — 弾切れ」を確認。
- 右クリックの `contextmenu.defaultPrevented === true` を確認。
- ゲーム内部の固定状態（energy=0、全砲クールダウン0）で主砲のエネルギー枯渇経路を実行し、HUDのエネルギー0を確認。
- 各確認画面のfullPage PNGとアクセシビリティsnapshotを保存。

ポーズ画面は初回証跡で重なりがあったが、`e2e-12-pause-visibility`でCSS修正後の6項目表示・クリック可能状態を再確認した。

## 補足

エネルギー枯渇の固定状態確認は、通常プレイでの自然な枯渇ではなく、Playwrightの状態注入で実施した。通常プレイでも戦闘による損傷・訓練中断まで確認済み。
