# 進め方とロードマップ

[02_改善案の詳細.md](02_改善案の詳細.md) の①〜⑰を、どの順で、どこまでやったら次へ進むかを決める資料です。
**実装はまだ行いません。** ここに合意が取れてから着手します。

---

## 全体の考え方

```
第1期  遊びとして成立させる      ①②⑥⑦        「4分で意味も分からず死ぬ」を無くす
  ↓
第2期  結果が積み上がる         ③④⑤⑧⑨⑭     「うまくやると違う」が分かる
  ↓
第3期  帰る場所を作る           ⑩⑪⑫⑬        艦内が読み物・判断の場になる
  ↓
第4期  本家超えの軸を立てる      ⑮⑯⑰         「誰を帰したか」で測るゲームにする
```

**第1期を飛ばして第3期や第4期をやらないこと。**
今回のプレイで分かったのは、艦内の作り込みや設定資料の量ではなく、
「一回の出撃が成立していない」ことが体験を止めているという事実です。

---

## 第1期 — 遊びとして成立させる

| 案 | 内容 |
|---|---|
| ① | 各章に必須目標を1〜2個置き、それが勝敗を決める。達成度を3段階にする |
| ② | 僚機の被弾／戦死に無線を付ける。自機撃墜に3〜5秒の間と爆発を入れる |
| ⑥ | 近距離の敵機に縁光とエンジン光。曳光弾を長く明るく。距離帯ごとの見せ方を決める |
| ⑦ | コクピット装飾を既定 ON。黒帯ではなく風防の柱と天蓋で囲む。外部視点ではダッシュボードを隠す |

### 第1期の完了条件（この5つが全部言えたら完了）

1. 難易度「ふつう」で第1章を通し、**帰投しただけでは勝てない**ことを確認できる。
2. 難易度「やさしい」で第2章を通し、**敵機の姿を見ながら1機以上撃墜できる**。
3. 僚機が撃墜されたとき、**その場で気づく**（無線か画面中央の表示のいずれかで）。
4. 自機が撃墜されたとき、**撃墜されたと分かってから**画面が切り替わる。
5. コクピット視点と外部視点のキャプチャを並べて、**別の視点だと一目で分かる**。

## 第2期 — 結果が積み上がる

| 案 | 内容 |
|---|---|
| ③ | 状態値を出撃中の行動から動かす。デブリーフに内訳を1行ずつ出す |
| ④ | 章末選択を出撃結果から生やす。何もできなかった章では選択を出さない案も検討 |
| ⑤ | Nav 到着距離を 2〜4km に。タイマーは到着後に開始。旋回時の速度低下を見直す |
| ⑧ | 常時表示の目標を3行に。必須／任意を色分け。文字の背後に暗い帯。警告を2行にする |
| ⑨ | 被弾方向を画面端の光で示す。装甲図に直前の被弾面をハイライト。危険域の明示 |
| ⑭ | チュートリアルの完了条件を直し、任務終了後に表示を消す |

### 第2期の完了条件

1. 同じ第1章を「輸送船を守って帰る」「見捨てて敵を追う」の2通りでプレイし、
   **デブリーフの数値と章末選択の中身が違う**ことを確認できる。
2. Nav に到着した瞬間のキャプチャで、**その Nav の目標が画面に写っている**。
3. 制限時間つき目標が、**到着してから**カウントを始めている。
4. 戦闘中のキャプチャで、**目標表示が背景に埋もれずに読める**（太陽の前でも）。
5. 撃たれた方向が画面から分かる。

## 第3期 — 帰る場所を作る

| 案 | 内容 |
|---|---|
| ⑩ | 艦内パネルの高さを空きに合わせて広げ、入らない分はページ送り。名鑑に顔画像 |
| ⑪ | 会話を2〜3往復に。プレイヤーの返事を2択。関係値を表示し、出撃結果で内容を変える |
| ⑫ | 戦況マップを星系図にする。8戦域の状態、通った章、4状態の効き先を表示 |
| ⑬ | 4機をブループリント図で描き分け、性格を一言で添える。主人公選任に「変わること」を明記 |

### 第3期の完了条件

1. 艦内のどの画面でも、**文章が枠で切れていない**（1280×720 と 1366×768 の両方で確認）。
2. 名鑑から**36名すべて**を読める（ページ送りでよい）。顔がある人は顔が出る。
3. 酒場で誰かと話すと**2往復以上**あり、こちらの返事を選べる。
4. 戦況マップに**地図が描かれている**。
5. 格納庫の4機を並べたキャプチャで、**形の違いが分かる**。

## 第4期 — 本家超えの軸を立てる

| 案 | 内容 |
|---|---|
| ⑮ | 救助を操作にする。減速・静止・収容。搭乗者名の表示。連れ帰った名前の一覧 |
| ⑯ | 敵エースへの通信（名乗る／降伏勧告／決闘）。ポッドを撃たない選択が次に効く |

### 第4期の完了条件

1. 脱出ポッドを**自分の操作で**収容でき、収容した人の名前が表示される。
2. デブリーフに「連れ帰った人」の一覧が出る。
3. 最終章の無線で読み上げられる名前が、**自分が連れ帰った人**である。
4. 敵エースと2つ以上の章で再会し、会話が前回を踏まえている。

## 各期の後に必ず行う確認

`AI_CODING.md` の方針に沿って、期ごとに以下を通します。

- `npm run typecheck` / `npm test` / `npm run build`
- 1280×720 と 1366×768 で、タイトル → 艦内 → ブリーフィング → 出撃 → 戦闘 → デブリーフを1本通す
- **実キー入力**でのプレイ確認（`dispatchEvent` だけの確認を合格としない）
- 各画面のキャプチャを `.tmp/` に残し、前回のキャプチャと並べて比較する

## やらないこと（今回の範囲外として明示）

膨らませないために、以下は今回の改善案に含めません。

- 実 3D アセット（GLTF）の外注・制作
- 実音声のボイス収録
- マルチプレイ
- ミッションエディタ
- 新しい章・新しい勢力の追加（**中身は足りていない側の問題ではない**）

理由: いま足りないのは量ではなく、**既にあるものがプレイヤーに届く経路**です。
新規コンテンツを足すと、届かないものが増えるだけになります。

## 判断が必要な点（着手前に決めたいこと）

1. **撃墜されたときに戦役を止めるか。**
   現状は勝利点 −2 で次章へ進む。「死が軽い」問題の中心だが、
   十章を必ず通せる設計方針（README に「敗北しても次章へ進む」と明記）と衝突する。
   - 案A: 章は失敗扱いにするが進行は止めない（記録に「機体喪失」を残す）
   - 案B: その章をやり直させる（既にある「この任務をやり直す」を正規ルートにする）
2. **任意目標をどこまで必須に上げるか。**
   第1章の7項目のうち、必須にすべきは1〜2個という提案だが、どれを選ぶか。
3. **コクピットの視界をどこまで狭めるか。**
   本家に寄せるほど前方視界は狭くなる。中央 60% を抜けにする案で良いか。
