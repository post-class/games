## W7-2 既定キーを `+` `-` にする

### 現状

```ts
  throttleUp: 'BracketRight',   // ]
  throttleDown: 'BracketLeft',  // [
```

`InputManager.update()`（309-316 行）に、**既定のままのときだけ** `Equal` / `NumpadAdd`（`Minus` / `NumpadSubtract`）も
押しっぱなし判定に加える別名処理がある。エッジ入力（`handleEdge`）側にはこの別名が無いため、
現状 `+` の単押しは効かない（押し続けたときだけ効く）。

### 変更

1. 既定を入れ替える。

```ts
  throttleUp: 'Equal',      // + （Shift 無しの = キー。方針書 優先度2）
  throttleDown: 'Minus',    // -
```

2. 別名の仕組みを、押しっぱなしとエッジで**共通の1つの関数**にする。

```ts
/**
 * 速度設定キーの別名。
 * 方針書どおり `+` `-` を既定にしつつ、これまでの `]` `[` と
 * テンキーの `+` `-` も従来どおり効かせる。
 * 既定から割り当てを変えた人には別名を効かせない（自分で選んだキーだけが効く）。
 */
const THROTTLE_ALIASES: Record<'throttleUp' | 'throttleDown', string[]> = {
  throttleUp: ['Equal', 'NumpadAdd', 'BracketRight'],
  throttleDown: ['Minus', 'NumpadSubtract', 'BracketLeft'],
};

private throttleKeyHit(binding: 'throttleUp' | 'throttleDown', code: string): boolean {
  if (settings.keyBindings[binding] === code) return true;
  if (settings.keyBindings[binding] !== DEFAULT_KEY_BINDINGS[binding]) return false;
  return THROTTLE_ALIASES[binding].includes(code);
}
```

- `handleEdge()`（280-281 行）を `this.throttleKeyHit('throttleUp', code)` に置き換える。
- `update()`（309-318 行）の `up` / `down` 判定を、
  `[...this.keys].some((c) => this.throttleKeyHit('throttleUp', c))` 相当の形へ置き換える
  （`keys` が Set なので、別名配列側を回して `keys.has()` を見る形が安い）。
- `shouldPreventDefault()` は既に `Equal` / `Minus` / `NumpadAdd` / `NumpadSubtract` を含む。
  `BracketRight` / `BracketLeft` は `Object.values(settings.keyBindings).includes(code)` で
  拾えなくなるので、**明示的に加える**（`]` を押したときにブラウザ既定動作が出ないようにする）。
- `KEY_LABELS` に `Equal: '+'` を追加する（現在は `'='` と出る。速度設定のキーとしては `+` と読ませる）。

**壊してはいけないこと**: キー割り当てを変更した保存データは `mergeKeyBindings()` が
そのまま復元する。**既定値を変えたので、旧既定（`]` `[`）を保存している人は `]` `[` のまま**になる。
これは意図どおり（自分で設定した値を尊重する）だが、
`migrateSettings()` では**引き上げない**（キー割り当ては本人の設定物なので勝手に変えない）。
この判断をコメントに書く。

## W7-3 `L` による手動ミサイルロック

### 方針書の要求

> ミサイルを手動ロック / WC: L / 本作: 自動ロックのみ / **L と手動ロック仕様を追加**

### 仕様

- 設定「ミサイルロック」を追加する: `auto`（既定・現状の挙動） / `manual`。
- `manual` のとき、`updateMissileLock()` は **`L` でロックを開始した後だけ**進む。
  - `L`: 現在のターゲットに対してロック開始（`lockArmed = true`、`lockProgress` は 0 から）。
  - ロック中に条件（射程 `LOCK_RANGE` / 視野 `LOCK_CONE`）を外れたら `lockArmed` を落として
    `lockProgress` を減衰させる（自動と同じ減衰式を使う）。
  - ターゲット変更・副兵装切替・発射・脱出で `lockArmed = false`。
  - 無誘導（`seeker === 'none'`）は従来どおり常時ロック済み扱い（`L` は不要）。
- `auto` のときも `L` は効く（**ロックのやり直し**: `lockProgress` を 0 に戻して再ロック）。
  ロックが古い目標に張り付いたと感じたときの操作として意味を持たせる。

### 手順

1. `src/app/settings.ts`
   - `ControlBinding` に `'manualLock'` を追加。`DEFAULT_KEY_BINDINGS.manualLock = 'KeyL'`。
   - `CONTROL_BINDINGS` に `{ id: 'manualLock', label: 'ミサイル手動ロック' }`（ミサイル系の隣）。
   - `Settings` に `missileLock: 'auto' | 'manual'`（既定 `'auto'`）。`normalizeSettings()` で 2値へ丸める。
   - 補足: `KeyL` は艦内の名鑑パネル切替（`src/ui/HubPanels.ts:157` の `chapter: 'KeyL'`）と
     同じコードだが、**画面が排他**（艦内 / 出撃中）なので衝突しない。コメントで明記する。
2. `src/app/input.ts`
   - `InputAction` に `'manualLock'`、`EDGE_BINDINGS` に `['manualLock', 'manualLock']` を追加。
   - `KEY_LABELS` は `KeyL` → 既定処理で `L` と出るので追加不要。
3. `src/world/entity.ts`
   - `ShipRuntime` に `lockArmed: boolean` を追加。`src/world/world.ts` の
     `makeShipRuntime()` で `lockArmed: false` を初期化する。
4. `src/sim/weapons.ts` `updateMissileLock()`
   - 引数へ `manual: boolean` を渡す（`simulateStep` のオプション経由。
     `playerWeaponModifiers` と同じ流し方にする）。**AI には常に `false`**
     （敵が手動ロックを要求されると撃たなくなる）。
   - `inLock` の判定を `const inLock = distance < LOCK_RANGE && cone > LOCK_CONE && (!manual || ship.lockArmed);`
     へ変える。`inLock` が false のときに `manual` なら `ship.lockArmed = false` も落とす。
   - `bus.emit('lockChanged', { reason: ... })` に `'not-armed'` を追加し、
     手動でまだ `L` を押していない場合の理由を返す。
5. `src/app/game.ts` `handleActions()`
   - `case 'manualLock':` を追加。
     - ターゲットが無ければ `announce`「ロックする目標がない」。
     - あれば `ship.lockArmed = true; ship.lockProgress = 0; ship.lockedId = undefined;`
       と `audio` のロック音（`bus.emit('lockChanged', {...reason:'rearm'})` 経由）。
   - `cycleMissile()` / `setTarget()` / 発射処理 / `eject` の各所で
     既に `lockProgress = 0` にしているところへ `lockArmed = false` を並べる
     （`grep -rn "lockProgress = 0" src/sim src/world` の全箇所）。
6. `src/hud/HudView.ts:1586` 付近のロック表示に、
   `manual` かつ未 armed のときの表示 `□ ロック待機 [L]` を追加する。
   **「押せば進む」ことが画面から分かるようにする**（キーを増やすだけで説明しないと使われない）。
7. 設定 UI: 「操作」タブに `ミサイルロック ◀ 自動 / 手動 ▶` を追加し、
   説明文「手動では L を押した目標だけロックします」を添える。

## W7-4 目標速度へ同期（`;`）

### 仕様

- 押すと、**現在のターゲットの速度に自分の速度設定を合わせる**。
  `throttle = clamp01(目標の速度 / 自機の最高速度)`。
- ターゲットが無い／自機が最高速度 0 のときは `announce`「同期する目標がない」。
- 実行時に `announce`「速度同期 240 KPS（62%）」を出す（何をしたか分かるようにする）。
- アフターバーナー相当（目標が自機の最高速度より速い）のときは 100% で止める。
  「追いつけない」ことは HUD の速度差で読めるので、ここで AB を自動化はしない。

### 手順

1. `settings.ts`: `ControlBinding` に `'speedMatch'`、既定 `'Semicolon'`。
   `CONTROL_BINDINGS` へ `{ id: 'speedMatch', label: '目標速度へ同期' }`。
   `KEY_LABELS` に `Semicolon: ';'`。
   選定理由をコメントに書く: **`L` の隣で右手で押せて、未割り当てだったキー**。
   方針書の「資料上は V 系」は本作の `V`（HUD情報切替）と衝突するため採らない。
2. `input.ts`: `InputAction` に `'speedMatch'`、`EDGE_BINDINGS` へ追加。
   `shouldPreventDefault()` は `Object.values(keyBindings)` に入るので追加不要。
3. `game.ts` `handleActions()`: `case 'speedMatch':` を実装する。
   計算は**純関数として切り出す**（テストするため）。

```ts
// src/sim/flight.ts
/**
 * 目標の速度に合わせる速度設定を返す。
 * 目標が自機の最高速度より速ければ 100% で止める（AB は自動化しない）。
 * 目標が無い・最高速度が 0 のときは undefined（呼び出し側が案内を出す）。
 */
export function speedMatchThrottle(selfMaxSpeed: number, targetSpeed: number): number | undefined
```

4. `InputManager.throttle` を直接書き換える（ホイールや数字キーと同じ扱い）。
   `applyPlayerInput()` が次のフレームで `p.input.throttle` へ写す。

## W7-5 照準下の目標を選択（`I`）

### 現状との違い

`targetFront`（`Y`）は「機首方向 `cos > 0.75`（約 41°）の中で、正面度と距離を混ぜて選ぶ」。
方針書が求めるのは **照準そのものの下にいる相手を優先**する選択で、
交戦中に「いま撃っている相手」を掴むための操作である。

### 仕様

- `HudView` の固定照準（`core/aim.ts` の `AIM_ORIGIN_Y` / `AIM_PITCH_OFFSET`）の**射線**に
  最も近い相手を選ぶ。
- 敵だけでなく**非敵対も選べる**（識別のために中立船を掴む用途がある。第2章の主題）。
  ただし敵を優先する（同程度の角度なら敵）。
- 角度の許容は狭く（`cos > 0.985`、約 10°）。外れていたら
  `announce`「照準下に目標なし」。**`Y` の代わりにはしない**（役割を分ける）。

### 手順

1. `src/sim/targeting.ts` へ追加する。

```ts
/**
 * I キー: 照準の射線に最も近い相手を選ぶ。
 *
 * `targetFront`（Y）との違い:
 *   Y = 前方の広い円錐（約41°）から「正面度 × 近さ」で選ぶ（交戦相手を探す操作）
 *   I = 照準の射線ほぼ真上（約10°）にいる相手を選ぶ（いま撃っている相手を掴む操作）
 * 照準は機首より少し上を向いている（`AIM_PITCH_OFFSET`）ので、
 * 機首前方ベクトルではなく**照準の射線**を使う。ここを機首で代用すると
 * 「照準に入れているのに掴めない」が起きる。
 */
export function targetUnderReticle(
  world: World,
  self: Entity,
  aimPitchOffset: number,
): Entity | undefined
```

- 射線は `forwardOf(self.quat)` を機体右軸まわりに `aimPitchOffset` だけ回した向き。
  `src/core/aim.ts` に既に照準の定数があるので、**そこから読む**（数値を写さない）。
- 敵優先は `score = cos + (isHostile ? 0.01 : 0)` 程度の微差で表現する。
2. `settings.ts`: `'targetReticle'` を追加、既定 `'KeyI'`、ラベル `ターゲット 照準下`。
3. `input.ts`: `InputAction` に `'targetReticle'`、`EDGE_BINDINGS` へ追加。
4. `game.ts`: `case 'targetReticle':` で `targetUnderReticle(...)`。
   失敗時は `announce`「照準下に目標なし」（`durationMs: 1200`、他のターゲット系と同じ）。

## W7-6 僚機命令の Alt 系ショートカット

### 仕様

方針書の候補どおり、通信メニューを開かずに僚機へ命令できるようにする。

| キー | 命令 | メニューの番号 |
|---|---|---|
| Alt+F | 編隊を組め | 1 |
| Alt+A | 私の目標を攻撃 | 2 |
| Alt+B | 散開して交戦 | 3 |
| Alt+H | 支援に来い | 4 |
| Alt+R | 僚機の状況報告 | 5 |

- **メニューは開かない。** 命令だけ実行し、従来どおり無線と `announce` が出る。
- 通信機が故障しているとき（`commsAvailable()` が false）は
  従来と同じ「通信機が故障している」を出して何もしない。
- `Alt+E`（脱出）と衝突しない（`E` は含まれない）。
- ブラウザのメニューバーが反応しないよう `preventDefault()` する。

### 手順

1. `src/ui/CommsMenu.ts` に、メニューを開かずに基本項目を実行する口を足す。

```ts
  /**
   * 基本項目（1..5 固定）を、メニューを開かずに実行する。
   * Alt 系ショートカット（W7-6）用。エースページの項目は対象にしない
   * （交渉は「相手を選んで開いてから」の操作なので、ショートカットにしない）。
   */
  invokeBaseItem(index: number): boolean {
    const item = BASE_ITEMS[index];
    if (!item) return false;
    this.onPick(item.action as CommsAction);
    return true;
  }
```

2. `src/app/input.ts` `handleEdge()` の脱出判定（275 行）の隣へ追加する。

```ts

    // 数字キー経路 (`comms1..6`) と同じ action を積むので、処理は 1 か所のまま。
    if (ev.altKey) {
      const index = ALT_WING_ORDERS[code];
      if (index !== undefined) {
        ev.preventDefault();
        this.actions.push(`comms${index}` as InputAction);
      }
    }
```

```ts
/** Alt + キー → 通信メニューの項目番号（1..5）。方針書の Alt+F/A/B/H/R に対応する。 */
const ALT_WING_ORDERS: Record<string, number> = {
  KeyF: 1, KeyA: 2, KeyB: 3, KeyH: 4, KeyR: 5,
};
```

**注意**: `KeyA`（オートパイロット）と `KeyF`（視点切替）と `KeyR`（最至近ターゲット）は
既に単独で割り当てがある。`handleEdge()` の `EDGE_BINDINGS` ループは修飾キーを見ていないので、
**Alt+A を押すとオートパイロットも同時に走る**。
→ `EDGE_BINDINGS` のループを `if (!ev.altKey && !ev.ctrlKey)` で囲む。
   Alt/Ctrl 付きの入力は「修飾キー付きの操作」として別扱いにする、と決める（コメントに書く）。
   これで `Alt+E`（脱出）が `KeyE` のロールと二重に走らない現状の作りとも整合する。

3. `src/app/game.ts` の `comms1..6` 処理を分岐させる。

```ts

          const index = Number(a.slice(5)) - 1;
          if (this.comms.open) {
            this.comms.pickIndex(index);
            this.input.commsMode = this.comms.open;
          } else if (index <= 4) {
            // Alt 系ショートカット。メニューを開かずに僚機命令を出す

              bus.emit('announce', { text: '通信機が故障している', kind: 'bad' });
              break;
            }
            this.comms.invokeBaseItem(index);
          }
          break;
        }
```

4. ポーズ画面の操作方法（`showPauseHelp()`）へ1行足す:
   `<b>Alt+F/A/B/H/R</b> で僚機へ直接指示（編隊 / 私の目標 / 散開 / 支援 / 報告）。`

## W7-7 後方視点（`/` を押している間）

### 方針書の要求

> バックミラー／後方視点 … **本作で実装予定**。コクピット内バックミラーまたは専用の後方視点を追加

### どちらを採るか

**専用の後方視点（押している間だけ後ろを向く）を採る。**

- バックミラー（画面内の小窓）は、シーンを**2回描く**（追加のレンダーターゲット）ことになり、
  至近距離のコクピット内装・ブルーム・宇宙塵を含む現在の描画コストを倍近くにする。
- 後方視点はカメラの向きを反転するだけで追加描画が無い。
- 本家 WC も後方確認は「視点」で行う（`Prophecy` の後方視点）。

### 仕様

- `/`（`Slash`）を**押している間**、コクピット視点のカメラを後ろ向きにする。離すと戻る。
  - 押しっぱなし判定なのでエッジ入力ではなく `InputManager` の getter で読む（`afterburner` と同じ形）。
- コクピット内装は後ろを向いている間は隠す（前向きの風防が後方視界に重なるとおかしい）。
- HUD は「後方視点」であることを中央上に出す（`後方 [/]`）。
  照準・リード表示は後方視点では**出さない**（後ろは撃てない）。
- 追尾視点（`chase`）のときは何もしない（すでに機体の外にいる）。
- `Slash` は日本語キーボードでも `/` に対応する code なので既定として使える。

### 手順

1. `settings.ts`: `ControlBinding` に `'rearView'`、既定 `'Slash'`、
   `CONTROL_BINDINGS` へ `{ id: 'rearView', label: '後方視点（押している間）' }`。
   `KEY_LABELS` に `Slash: '/'`。
2. `input.ts`: 押しっぱなしの getter を足す。

```ts
  /** 後方視点キーを押しているか（押している間だけ後ろを向く）。 */
  get rearView(): boolean {
    return this.keys.has(settings.keyBindings.rearView);
  }
```

`shouldPreventDefault()` は `Object.values(keyBindings)` に入るので追加不要。
`onBlur` で `keys.clear()` されるので、押したままタブを離れても戻る。

3. `src/render/CameraRig.ts`
   - `rearView = false` のフィールドを足す。
   - `update()` のコクピット分岐で、`rearView` のとき
     `this.camera.quaternion.copy(q)` の後に **Y 軸まわり 180° の回転を掛ける**。

```ts
    if (this.mode === 'cockpit') {
      const eye = ...;
      this.camera.position.copy(eye);
      this.camera.quaternion.copy(q);
      // 後方視点: 機体姿勢のまま真後ろを向く（追加の描画はしない）
      if (this.rearView) this.camera.quaternion.multiply(REAR_TURN);
    }
```

`const REAR_TURN = new Quaternion().setFromAxisAngle(new Vector3(0, 1, 0), Math.PI);`
（モジュール定数。毎フレーム生成しない）

4. `src/app/game.ts`
   - `renderStep()` で `this.rig.rearView = this.active && !this.inputLocked && this.input.rearView;`
   - コクピットの表示は `setStyle(...)` の条件へ `&& !this.rig.rearView` を足す（W4 と合わせる）。
   - `this.hud.setRearView(this.rig.rearView)` を呼ぶ。
5. `src/hud/HudView.ts`
   - `setRearView(on: boolean)` を足し、`on` の間は
     - 照準・リード表示・ターゲット枠の**画面内投影**を出さない（`setExternalView` が
       既に似た制御をしているので、同じ経路に相乗りする）
     - 中央上に `後方 [/]` を出す
   - 速度・速度設定・ダメージ・目標一覧は**出したまま**にする
     （AI_CODING.md: 情報を消すと操作不能になる）。
