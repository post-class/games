## 現状

### 出撃中の ESC（ポーズ画面）— `src/app/App.ts:2162` `showPause()`


---

## あるべき姿

- 「第 3 章 / 全 10 章」と**単位つき**で出す。
- 1つの章に複数ミッションがある戦役（canon / expanded の敗北ルート）では
  「第 3 章 2本目 / 全 2本」も出す。1本しか無い章では章内表記を出さない。
- **同じ文字列**をポーズ画面とブリーフィング画面が使う（別々に組み立てない）。
- 敗北ルートのミッションであることは従来どおり分かる（`(戦況悪化)`）。

## 手順

### 手順 6-1 章内のミッション序数を出す純関数を足す

`src/content/campaign.ts` の末尾（`reachableCampaignNodes` の隣）へ追加する。

```ts
/** 章の中でのミッションの位置。1章に1本しか無い章では total が 1 になる。 */
export interface ChapterPosition {
  chapter: number;
  totalChapters: number;
  /** 章内の 1-based 序数 */
  index: number;
  /** 章内のミッション総数 */
  total: number;
}

/**
 * 章の中で、そのノードが何本目のミッションかを返す。
 *
 * 章内の並び順は「勝ちルート優先 → ノード id 昇順」で安定させる。
 * グラフの到達順で並べないのは、敗北ルートを含む章では順路が枝分かれし、
 * 「何本目」が経路によって変わってしまうため。
 * ここは**表示のための安定した番号**であり、進行の順序そのものではない。
 */
export function chapterPosition(
  id: CampaignNodeId,
  mode: CampaignMode = 'expanded',
): ChapterPosition
```

実装方針:

```ts
  const graph = campaignGraph(mode);
  const node = campaignNode(id, mode);
  const siblings = Object.keys(graph)
    .filter((key) => graph[key].chapter === node.chapter)
    .sort((a, b) => {
      const la = graph[a].losingRoute ? 1 : 0;
      const lb = graph[b].losingRoute ? 1 : 0;
      return la - lb || (a < b ? -1 : a > b ? 1 : 0);
    });
  return {
    chapter: node.chapter,
    totalChapters: totalChapters(mode),
    index: Math.max(1, siblings.indexOf(id) + 1),
    total: Math.max(1, siblings.length),
  };
```

- 終端（`victory` / `defeat`）は `campaignNode()` が投げる／持たないので、
  **呼び出し側で `isTerminal()` を先に見る**。`chapterPosition()` は
  ノードが存在する前提でよい（`campaignNode()` の既存の振る舞いに合わせる）。

### 手順 6-2 表示文を1か所で作る

`src/app/App.ts` にプライベートメソッドを足す（`chapterOf()` の隣）。

```ts
  /**
   * 「いま何章の何本目か」の表示文（W6）。
   *
   * ポーズ画面とブリーフィング画面が同じ文字列を使う。
   * 章内に1本しか無い戦役（veil の全章）では章内表記を省く
   * （「1本目/全1本」は情報が無いのに横幅を食う）。
   */
  private progressLabel(): string {
    if (isTerminal(this.save.node)) return '';
    const p = chapterPosition(this.save.node, this.save.campaignMode);
    const chapter = `第${p.chapter}章 / 全${p.totalChapters}章`;
    const within = p.total > 1 ? `　ミッション ${p.index}/${p.total}` : '';
    return `${chapter}${within}`;
  }
```

### 手順 6-3 ポーズ画面へ出す

`showPause()` の `bodyHtml` を差し替える。

```ts
      bodyHtml:
        `<div class="mc-progress">${escapeHtml(this.progressLabel())}</div>` +
        `<div class="dim">${escapeHtml(this.currentMission().title)}</div>` +
        `<div class="dim">${escapeHtml(this.currentMission().system)}　難易度: ${escapeHtml(difficulty().label)}</div>`,
```

- 1行目に進行、2行目に題名、3行目に星系と難易度。
  **3行を超えない**（ポーズ画面は項目が6つあるので、狭い画面で項目が押し出される）。
- `.mc-progress` を `src/styles/ui.css` へ追加する。
  文字は 16px（基準サイズ）、色は `--friend` 系のアクセント、下に 4px の余白。
  **ヘッダを大きくしない**（AI_CODING.md のコーディング規約）。

### 手順 6-4 ブリーフィング画面へ出す

`showBriefing()` の `subtitle` を差し替える。

```ts
      subtitle:
        this.save.campaignMode === 'veil'
          ? `${this.progressLabel()}　${node.seriesName}　—　${def.system}`
          : `${this.modeLabel(this.save.campaignMode)}　${this.progressLabel()}　${node.seriesName}` +
            `　—　${def.system} 星系${node.losingRoute ? '　(戦況悪化)' : ''}`,
```

- veil は題名に「第1章 …」が入っているため章番号が二重になるが、
  **副題の方は「/ 全10章」を持つ**ので情報が違う（あと何章あるかが分かる）。
  重複を嫌って消すと「全体のどこか」が読めなくなるので、残す。
- 横幅が溢れる場合は `modeLabel` を落とす（veil が既定なのでモード名の価値が低い）。
  1280×720 で実測してから決める。

### 手順 6-5 セーブ表示との整合（任意だが推奨）

## 検証

- 単体（`chapterPosition`）:
  - veil の全10章それぞれで `index === 1 && total === 1`、`totalChapters === 10`。
  - expanded で敗北ルートを持つ章の勝ちルートノードが `index === 1`、
    敗北ルートノードが `index === 2`、`total === 2`。
  - 同じノードを何度呼んでも同じ番号（安定順であること）。
  - `canon` の章数が 7、`expanded` が 9 であること（既存 `totalChapters` と一致）。
- 単体（`progressLabel` 相当のロジック）: `total === 1` のとき章内表記が出ない。
- ブラウザ（1280×720）:
  - 第1章のブリーフィングで副題に `第1章 / 全10章` が出る。
  - 出撃して ESC を押し、ポーズ画面の1行目に `第1章 / 全10章`、
    2行目に題名、3行目に星系と難易度が出る。ポーズの項目6つが画面内に収まる。
  - `expanded` で新規開始し、敗北ルートへ入ったミッションのブリーフィングで
    `ミッション 2/2` と `(戦況悪化)` の両方が出る。
