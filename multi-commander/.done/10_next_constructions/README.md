# 10_next_constructions — 「素晴らしいゲーム」への構築計画

現行の multi-commander は、設計の骨格は良いが**見た目・手触り・音・コンテンツ・物語が薄い**プロトタイプである（＝「チープ」）。
本ディレクトリは、これを初代要望——**「ウィングコマンダーと同等か、それ以上に面白いゲーム」**（`../00_initila_constructions/00_youbou.md`）——に本気で引き上げるための計画一式である。

---

## 0. まず結論（30秒で）

- **作り直しではなく肉付け。** ECS・データ駆動の機体/ミッション・GLTF差し替え口・イベントバスという良い土台は活かす。
- **チープさは「量産的な欠落」に集中。** 最速で効くのは **見た目 → 手触り → 音**（Phase 1〜3）。ここを終えるだけで「安っぽい」評価はほぼ覆る。
- **その後に奥行きと物語**（Phase 4〜7）を、データ駆動の強みで積み増す。
- 全体を **Phase 0〜8** の縦切り（各段が単体で出荷可能）で進める。**最重要の分水嶺は Phase 1〜3 完了時点**。

## 3. この計画を貫く原則

1. **体感品質の伸び ÷ 工数** が大きい順に前倒す（見た目・手触り・音が先）。
2. **各フェーズは縦切り**：途中で止めても「前より良い」。
3. **仕組みを先に、素材は後に**：GLTF/音源の差し替え口を先に作りプレースホルダで疎通。
4. **データ駆動に寄せる**：機体・ミッション・武装・会話を“足せば増える”形に。
5. **良い骨格を壊さない**：既存30テストを緑に保ちながら肉付けする。

詳細な思想は [`02`](./02_ビジョンと設計の柱.md)、順序の根拠は [`03`](./03_ロードマップ.md) を参照。

---

## 4. 「素晴らしい」の定義（合否ライン）

計画完遂後、[`02` §3](./02_ビジョンと設計の柱.md) の縦の体験（起動→ブリーフィング室→出撃→交戦→山場→撃墜演出→デブリーフ）の**どこにも安っぽさが無い**こと。
各フェーズの具体的な合否は [`08`](./08_マイルストーンと受け入れ基準.md) の受け入れ基準と体感チェックで判定する。
