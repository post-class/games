# ウィングコマンダーを超えるためにやること

現状（2026-08-03 時点）は「飛んで撃って、8ミッションのキャンペーンを通せる」段階。
遊べるが、ウィングコマンダー（以下 WC）が持っていた**「戦争の中で生きている感覚」**がまだ無い。

このファイルは、
1. WC にあって今の実装に無いもの（＝同等になるための課題）
2. WC にも無かったもの（＝超えるための課題）
3. 単純に壊れている・未接続なもの（＝すぐ直すべき負債）
に分けて課題を並べる。優先度は **P1（これが無いと WC に届かない）** > **P2（超えるための差別化）** > **P3（あると良い）**。

---

## 0. まず直すべき負債（実装が中途半端な箇所）

小さいが、放置すると「作りかけ」の印象を与える。

- [x] **`N` キー（Nav マップ）が無反応** → `hud/NavMap.ts` を追加。航路・Nav・機体・艦艇を上から見た平面図で表示し、
  次の目的地と距離、スケールバーを出す。`N` で開閉
- [x] **死んだ設定項目が3つある** → すべて実装に接続
  - `settings.aimAssist` → `sim/weapons.ts` の `applyAimAssist()`。ほぼ狙えているとき (0.075 rad 以内) だけ
    射線を予測点へ最大 0.05 rad 寄せる。外れているときは一切補正しないので「勝手に当たる」感覚にはならない
  - `DifficultyProfile.strongAimHelp` → やさしいのみ補正を最大 (1.0)、他は 0.45
  - `DifficultyProfile.fuelScale` → `ShipRuntime.fuelMax` を追加し、AB 燃料の上限に倍率を適用
- [x] **脱出（Eject）が未実装** → `sim/eject.ts`。`Alt+E`（誤操作防止のため2回押し確認）で脱出。
  機体は武装と機動を失い、陣営が中立になって敵に狙われなくなる。ミッションは「機体喪失」で失敗するが命は残る
- [x] **僚機が死んでも何も起きない** → 1-2 のパーマデス／名簿で解消。戦死は永続し、追悼画面が入り、
  残った隊員の関係値が下がる
- [x] **衝突ダメージが雑** → 相対速度に閾値を設け（40 未満は擦り傷）、二乗で効かせるように変更。
  さらに半径比を質量比として扱い、小さい機体が大きく損傷する。艦艇への激突はほぼ致命傷になる
- [x] **全機体が同じ飛行モデルの数値違い** → `ShipDef.handling` を追加
  - `drift`: 旋回時に速度が機首へ追いつく遅さ。大きいほど機体が流れる
  - `turnSpeedPenalty`: 最高速付近で失う旋回性能。大きい機体は「曲がりたければ絞る」判断を強いられる
  - 軽戦闘機 (0.10〜0.16) から重戦闘機 (0.24〜0.36)、艦艇 (0.8〜0.9) まで段階を付けた

**この作業中に見つけて直した設計上の詰み:**

- [x] **戦闘目標を達成しても敵が残っていると帰投できず詰む** — オートパイロットが敵在圏で使えないため、
  「輸送艦を破壊した、あとは帰るだけ」の状態で 34km を巡航速度で飛ぶしかなかった。
  `MissionRunner.canDisengage` を追加し、戦闘系の必須目標を片付けていれば
  敵がいても「戦域離脱」としてオートパイロットを許可するようにした

## 1. WC に届くために必要なもの（P1）

### 1-1. 母艦での生活 ＝ 最大の欠落

WC の魅力の半分は「ミッションと次のミッションの間」にあった。今の実装はブリーフィング画面しかない。

- [x] **タイガーズ・クロー艦内をハブ画面にする** → `App.showHub()`。以下5室を実装
  - **ブリーフィング室** … 現在の実装（作戦図はある）
  - **酒場 / レクリエーション室** … 僚機と会話し、性格・関係・戦況の噂を聞く。WC の "Rec Room" 相当。**ここが最も効く**
  - **バラック（自室）** … セーブ、名簿、戦績確認
  - **格納庫 / 飛行甲板** … 機体とロードアウトの選択、整備兵の台詞
  - **キルボード** … 全パイロットの撃墜数ランキング（自分の順位が見える）
- [x] **発艦・着艦シーケンス** → `app/DeckSequence.ts`。母艦を後方に置いてカタパルトで射出 (3.4秒)、
  帰投時は着艦誘導 (3.6秒)。演出中は台本が入力を奪うので「いきなり宇宙に居る」状態が無くなった
- [x] **勲章授与式と昇進** → `app/medals.ts`（階級6段・勲章8種）と `App.showCeremony()`。
  勲章と階級章は生成した透過 PNG で表示する

### 1-2. 僚機をキャラクターにする

今は名前と技量パラメータだけ。WC の Maniac / Spirit / Angel / Bossman は「人」だった。

- [x] **出撃前に僚機を選べるようにする** → 格納庫で選択。負傷・戦死者は自動的に候補から外れる
- [x] **性格を飛び方と無線に反映する** → `content/pilots.ts` に6性格（従順さ/攻撃性/慎重さ/根性/成長率）。
  従順さが低いパイロットは「編隊を組め」を無視して飛び出す (`ai.ts` の `isDisobeying`)。台詞も性格別
- [x] **僚機の永続死（パーマデス）** → `app/roster.ts` の `applySortie()`。戦死は `status='dead'` で永続し、
  酒場に空席が残り、追悼画面が入る。補充は来るが同じ人間ではない
- [x] **僚機の成長と負傷** → 生還で技量 +0.018×成長率、残ハル 30% 未満で 2〜3 回欠場
- [x] **僚機との関係値** → 救援 +0.3 / 置き去り −0.35。見殺しにすると他の隊員も −0.25。酒場の口調が変わる
- [x] **通信画面に顔（ポートレート）を出す** → `ui/Portrait.ts` の手続き生成 SVG。表情差分5種、
  無線の声に合わせて口が動く

### 1-3. 損傷を「機能の喪失」にする

現在の被弾は HP が減るだけ。WC は**壊れた部位の機能が失われる**のが恐怖だった。

- [x] **サブシステム損傷モデル** → `sim/subsystems.ts`。7部位を `ok / damaged / dead` の3段階で持つ。
  ハルに通ったダメージ量と残ハル率から確率判定し、**被弾面で壊れる部位が偏る**
  （左から撃たれれば左舷砲、後ろからならエンジン、正面ならレーダー）ので、
  「どちらを向けて逃げるか」がプレイに入ってくる
  - [x] レーダー故障 → 走査線ノイズが乗り、機体の表示位置がぶれ、一部が映らなくなる。損失で完全に沈黙
  - [x] 砲の片方が沈黙 → 左右別々に管理。damaged は 40% の確率で不発、dead で完全に沈黙し火力が半減する
  - [x] エンジン損傷 → 最大速度が 72%/40% に低下、損失で AB 使用不可
  - [x] シールド発生器損傷 → 再生速度が 40%、損失で完全に停止
  - [x] 通信機損傷 → 損失で通信メニューが開かなくなる（僚機へ指示できない）
  - [x] 姿勢制御損傷 → 旋回性能が 75%/45% に低下
- [x] **右 VDU の被害表示を「部位の生死」にする** → 装甲・シールドの残量バーの下に部位一覧を並べ、
  損傷は黄色、損失は赤で点滅させる
- [x] **損傷を抱えたまま帰投する判断** → 難易度に `playerSubsystemRate` を持たせて故障率を調整
  （やさしい 0.35 / ふつう 0.7 / むずかしい 1.15）。
  損傷が深い状態で飛び続けていると整備班と管制から無線が入り、帰投を促す

**この作業中に見つけて直したバグ:**

- [x] **接触ダメージが毎フレーム加算され、擦っただけで即死していた** — 60Hz で衝突判定が走るため、
  大型艦に寄りかかると 1 秒で数百ダメージ入っていた。実際に AI 操縦の自機が
  輸送艦を攻撃中に擦り続けて死ぬ現象が起きていた。
  接触は 0.5 秒間隔の離散的な衝撃として扱うようにし、押し戻しだけ毎フレーム行うよう分離した
- [x] **低速で接近する衝突を AI が回避していなかった** — 回避判定に接近速度の下限を設けていたため、
  ゆっくり寄っていく場合は回避が働かなかった。「すでに近すぎる」場合は速度に関係なく離れるようにした

### 1-4. 戦域を「場所」にする

今の宇宙は何も無い空間。WC には障害物があった。

- [x] **小惑星帯** — 漂流・自転する岩。撃てば砕けて分裂し、擦れば損傷。弾も遮る。小惑星帯の中ではオートパイロット不可
- [x] **機雷原** — 接近で起爆（敷設側の陣営には反応しない）。撃てば安全に処理できる。レーダーと航法マップに表示
- [x] **難民船・脱出ポッドなどの中立目標** — 脱出ポッド（接近で回収）と難民船（護衛対象）を追加
- [x] **恒星や巨大構造物のスケール感** — 実座標に置くランドマーク5種（ガス惑星／恒星／ジャンプゲート／ステーション／難破船）。遠景と違い飛ぶほど見え方が変わる

### 1-5. ミッション種別を増やす（今は 4 種）

現在は 全滅 / 護衛 / 破壊 / 生存 / Nav 到達 のみ。

- [x] **偵察（写真撮影）** — 目標を正面 20° / 1.2 km 以内に保持して撮影。`m2b-recon`（小惑星帯の奥の前進拠点）
- [x] **迎撃（爆撃機阻止）** — `m5b-intercept`。制限時間 4 分、雷撃機グラサを全機落とす。味方の機雷原が減速帯になる
- [x] **捜索救助** — `m3b-sar`。脱出ポッド3基を回収しつつ難民船を守る。撃たれたポッドは戻らない
- [ ] **哨戒中の遭遇戦** — 何も起きないかもしれない。何も起きない任務が混じるから、起きたときが怖い
- [ ] **キャピタルシップ強襲** — 砲塔を1つずつ潰し、エンジンを止めてから魚雷を通す多段構成
- [x] **時間制限つきの防衛** — 目標種別 `timeLimit` を追加（超過で失敗）。`survive` にも残り時間表示

### 1-6. キャンペーンの規模と分岐

- [ ] **ミッション数を増やす** — 現在 11（勝ち9＋敗北2）。WC1 は 40 以上。少なくとも 20 前後まで
- [ ] **星系マップ上で戦線が動く** — 現在は固定の分岐グラフ。勝てばキルラー方面へ、負ければ地球方面へ後退する「押し引き」を可視化する
- [ ] **シリーズ（星系）単位の構成** — 数ミッションごとに星系が変わり、成否で次の星系が決まる
- [ ] **物語の決着を複数持つ** — 現在の VICTORY / DEFEAT は素朴。中間結末（辛勝、痛み分け）を用意する

### 1-7. 音と演出

- [x] **BGM に旋律を与える** — 音符として書き下した4系統（主題 / 戦闘 / 勝利 / 追悼）を `audio/score.ts` に作曲。
  戦闘曲は主題を刻みに崩したもの、追悼は主題を引き伸ばしたものなので、同じ旋律として聞こえる。
  緊張度で層とテンポが増減し、曲の切り替えはクロスフェードする
- [x] **無線に声を当てる（または声の代替）** — 帯域を絞ったパルス列で音節の輪郭を作り、話者名から基本周波数を決める（同じ人物は同じ声）。
  口調で抑揚の向きが変わり、前後にスケルチが入る。鳴っている秒数を HUD に返して顔の口を動かす
- [x] **オートパイロットのジャンプ演出** — 宇宙塵を長い筋に伸ばし（`SpaceDust.setWarp`）、画角を広げ、発光を強める。
  開始と終了に上昇/下降するスイープ音
- [x] **撃墜のカメラ演出** — エースを自分で落としたとき / 艦艇が沈むときだけ、時間を 0.38 倍に落として爆発の方へ視線を寄せる

## 2. WC を超えるために必要なもの（P2）

WC と同じものを作っても超えられない。ここが差別化点になる。

### 2-1. 飛行隊シミュレーション（WC が持っていなかった深さ）

- [ ] **squadron 管理レイヤー** — プレイヤーは1機のパイロットでありつつ、飛行隊の編成を決める
  - 誰を出すか、誰を休ませるか、損傷機の修理をどう回すか
  - 補充で来る新人は技量が低く、育てるか使い捨てるかの選択が生まれる
- [ ] **補給の有限性** — ミサイルとフレアは母艦の在庫から出る。護衛任務で輸送艦を守れたかが在庫に直結する（＝失敗が次の任務を苦しくする因果）
- [ ] **戦況の数値化と可視化** — 制宙域、敵の戦力、補給線。プレイヤーの戦果が戦況テーブルを動かし、次のミッション生成に効く

### 2-2. 動的キャンペーン（固定分岐を超える）

- [ ] **手続き生成ミッション** — テンプレート＋戦況からミッションを組み立て、キャンペーンを無限に続けられる
- [ ] **敵エースの永続化** — 逃がしたエースは名前と機体を覚えていて、後のミッションに再登場し、腕が上がっている。倒すまで付いて回る「宿敵」
- [ ] **敵側の意思** — 敵も補給線を持ち、こちらが叩けば弱くなる。放置すれば増える

### 2-3. 操作と手触りの現代化

- [ ] **ゲームパッド対応** — 現在はキーボード＋マウスのみ。スティックでの飛行が最も気持ちいい
- [ ] **キー再割り当て機能** — 現在は完全に固定。設定画面から変更できるようにする
- [ ] **飛行モデルの選択を前面に出す** — Newtonian モードは実装済みだが「高度な操作」に隠れている。別ゲームとして遊べる深さがあるので、モード選択として見せる
- [ ] **リプレイ / キルカム** — 撃墜の瞬間を見返せる。共有したくなる
- [ ] **訓練シミュレータ** — 母艦に「訓練室」を置き、任意の敵と好きな条件で練習できる（WC1 には無かった）

### 2-4. アクセシビリティ（現代の必須要件）

- [ ] **色覚多様性への配慮** — 敵赤／味方青の識別を形状でも冗長化する
- [ ] **字幕と読み上げ速度の調整** — 無線ログの表示時間を設定可能にする
- [ ] **操作補助の段階** — 照準アシスト（現在は設定だけあって未実装）、自動水平、旋回補助
- [ ] **画面揺れ・明滅の抑制オプション** — 現在の被弾ビネットとブルームは酔いやすい人には強い

### 2-5. マルチプレイ

- [ ] **協力プレイ** — 僚機の席を人間が座る。WC の「僚機に指示する」体験が一気に生きる
- [ ] **対戦（ドッグファイト）** — 飛行モデルと武装はすでに対称なので、通信層を足すだけで成立する

## 4. 進める順番の提案

「WC に届く」ことを先にやる。順番を間違えると、豪華だが空虚なものになる。

1. **負債の解消**（第0章）— 半日。壊れている箇所を残したまま先へ行かない
2. **サブシステム損傷**（1-3）— これが入るだけで戦闘の緊張が別物になる。既存の `damage.ts` の拡張で済む
3. **母艦ハブ ＋ 僚機のキャラクター化とパーマデス**（1-1, 1-2）— WC らしさの本体。ここが最も投資効果が高い
4. **ミッション種別と戦域の障害物**（1-4, 1-5）— 遊びの幅
5. **音楽の作曲と演出**（1-7）— 記憶に残るかどうかを決める
6. **キャンペーン拡張**（1-6）— 中身が出来てから量を増やす
7. **飛行隊シミュレーションと動的キャンペーン**（2-1, 2-2）— ここで初めて WC を超える
8. **操作の現代化・アクセシビリティ・マルチ**（2-3, 2-4, 2-5）

## 5. 判断基準（「超えた」と言えるかの目安）

実装量ではなく体験で測る。

- [ ] **僚機の名前を、プレイヤーが自分から口にするか** — 「Spirit が落ちた」と言わせられたら 1-2 は成功
- [ ] **損傷して帰投するとき、手に汗をかくか** — 1-3 の成否
- [ ] **ミッション間に「寄り道」したくなるか** — 酒場に行く理由があるか。1-1 の成否
- [ ] **負けた後に、続けたくなるか** — 敗北ルートが罰ではなく物語になっているか
- [ ] **同じ戦域をもう一度飛びたくなるか** — 動的キャンペーンの成否
- [ ] **BGM を口ずさめるか** — 1-7 の成否
