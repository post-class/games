## 0. この手順書の使い方（AI 向け運用ルール）

### 0.1 作業の単位

- 作業単位は **タスク**。ID は `T-<マイルストーン>-<連番>`（例 `T-M4-03`）。
- **1 タスク = 1 コミット**。コミットメッセージは `T-M4-03 村人の搬入距離ペナルティ` の形式。
- タスクは必ず「依存」に挙がったタスクが**完了条件を満たしてから**着手する。
- 1 タスクの想定規模は **200〜400 行以内**。超えるならタスクを分割し、`§13 進捗台帳` に追記する。

### 0.2 着手時の手順（毎タスク共通）

1. `§13 進捗台帳` の該当行を `WIP` にする。
2. 該当タスクの「参照」に書かれた上流資料の該当セクションを読む。
3. 実装する。**同時にそのタスクのテストを書く**（テスト不要と明記されたタスクを除く）。
4. `npm run check`（型チェック + lint + テスト）が通ることを確認。
5. 「完了条件」を 1 つずつ目視・テストで確認。
6. 台帳を `DONE` にしてコミット。

### 0.3 禁止事項（決定論を壊すもの）

シミュレーション層（`src/sim/**`）では以下を**絶対に使わない**。CI の lint ルールで機械的に禁止する（`T-M0-05`）。

| 禁止 | 理由 | 代替 |
|---|---|---|
| `Math.random()` | 再現不能 | `Rng`（`§4.3`） |
| `Date.now()` / `performance.now()` | 再現不能 | `world.tick` |
| 浮動小数点演算（`/`, `*` の結果を小数で保持） | 端末差が出る | 固定小数点 `Fx`（`§4.2`） |
| `Object.keys()` / `Map` / `Set` の反復順に依存した処理 | 挿入順依存でバグが出やすい | ID 昇順にソートした配列 |
| `Array.prototype.sort` の非安定・非全順序比較 | 実装差 | 必ず ID をタイブレークに入れる |
| DOM / Canvas / WebSocket の参照 | 層の分離違反 | 描画層・通信層に出す |

### 0.4 判断に迷ったときの優先順位

1. `07_ゲームシステム.html`（内部規則・数値）
2. `03_文明と進化.html`（要素一覧・数値）
3. `06_操作方法.html` / `05_画面説明.html`（UI・操作）
4. `02_世界観.html`（設定の整合）
5. `01_ゲーム宣伝.html`（対外表現。数値の根拠には使わない）

矛盾を見つけたら**実装を止めずに**、`docs/ISSUES.md` に `[矛盾] 07§4 と 06§4 で早馬の効果が…` の形式で記録し、上位資料の値を採用して進める。

### 0.5 数値の扱い

上流資料の数値は「設計時の想定値」。**すべて `src/data/*.json` に出す**。コード内に数値リテラルを直接書かない（`§5`）。バランス調整は JSON の編集だけで完結すること。

## 1. 完成物の定義

### 1.1 一文で

ブラウザだけで動く、斜め見下ろし高精細 2D の歴史 RTS。8 文明・4 時代・最大 8 人対戦。中核は**最大 6 戦域に「令」を配って半自動で戦わせる戦域指令システム**。

### 1.2 完成の判定条件（Definition of Done, プロジェクト全体）

- [ ] `npm run build` で静的ファイル一式が出力され、静的ホスティングで動く
- [ ] タイトル → スカーミッシュ → 30 分試合 → 結果 → リプレイが一周する
- [ ] 8 文明すべてが選択でき、`03` の兵種ツリー・穴（持たない役割）が実装どおり
- [ ] 戦域が自動発生し、令 6 種＋固有令 8 種が `07§5` の重み定義どおり動く
- [ ] 2 端末のロックステップ対戦で 30 分間デシンクしない
- [ ] リプレイ再生の結果ハッシュが元試合と一致する
- [ ] 統合 GPU ノートで **描画 60fps / ユニット 400 体**を維持
- [ ] キャンペーン 4 章 20 ミッションがプレイ可能
- [ ] 操作は**キーボードを一切使わずマウスのみで 6 戦線運用可能**（`06§12`）

### 1.3 スコープ外（今回作らない）

- モバイル対応・タッチ操作（PC ブラウザのみ）
- アカウント／ランキング／マッチメイキング（URL 共有のみ）
- 音楽・ボイス（効果音の枠だけ用意し、無音でも成立させる）
- ゲーム内マップエディタ

## 2. 技術スタック

| 領域 | 採用 | 理由・注意 |
|---|---|---|
| 言語 | TypeScript 5（`strict: true`, `noUncheckedIndexedAccess: true`） | `01` の記載どおり |
| ビルド | Vite 6 | 開発サーバ HMR、静的出力 |
| 描画 | **Canvas 2D 自前レンダラ**（WebGL は使わない） | `01` の方針。スプライトバッチ + オフスクリーンキャッシュで 60fps を狙う |
| UI（HUD・メニュー） | **Canvas ではなく DOM + CSS** | 13 画面の実装コストを抑える。戦場のみ Canvas |

| サーバ | Node 24 + `ws` | ロックステップ中継のみ。ゲームロジックを持たない |

| 画像 | WebP（ユニット・建物）/ PNG 透過（UI 素材） | 生成は `img-gen-gpt` スキル |

### 3.1 層の依存方向（違反は lint で落とす）

```
data ──▶ sim ──▶ render ──▶ ui
          ▲        ▲         │
          │        └─────────┘
        input ◀───────────────┘
          │
   ai ────┤
   net ───┤──▶ command のみを sim に渡す
 replay ──┘
```

- `sim` は他の層を **import してはならない**（`shared` と `data` のみ可）。
- `render` / `ui` は `sim` を **読み取り専用**で参照する。状態を直接書き換えない。
- `sim` の状態変更は**すべて `Command` 経由**。これが対戦・リプレイ・AI を同一機構にする根拠（`07§12`）。

## 4. 決定論シミュレーションの設計

### 4.1 tick モデル

| 項目 | 値 | 出典 |
|---|---|---|
| シム tick | **25 tick/秒**（1 tick = 40ms） | `01`「ロジックは 25fps」 |
| 描画 | 可変（目標 60fps）。tick 間を補間 | 同 |
| ゲーム速度 0.5〜1.5 | **tick レートではなく `tickBudget` で調整**（1 描画フレームで進める tick 数） | `07§14`。tick 数そのものを変えると決定論が崩れるため |
| 試合長 | 約 30 分 = **45,000 tick** | `07§2` |

```ts
// sim/index.ts
export function stepWorld(w: World, cmds: readonly Command[]): void
// cmds は「この tick に確定した全プレイヤーの入力」を playerId 昇順、
// 同一 playerId 内は発行順に並べた配列。順序が変わると結果が変わる。
```

描画側のループ:

```ts
let acc = 0;
function frame(dtMs: number) {
  acc += dtMs * speedMul;
  let steps = 0;
  while (acc >= 40 && steps < 5) {       // 上限 5: 遅い端末で暴走させない
    stepWorld(world, inputSource.take(world.tick));
    acc -= 40; steps++;
  }
  render(world, acc / 40);               // acc/40 = 補間係数 alpha
}
```

### 4.2 固定小数点 `Fx`

座標・体力・資源・速度はすべて **整数**で持つ。小数が必要な量は 1/256 単位のスケール整数（Q8）。

```ts
// sim/core/fx.ts
export type Fx = number;              // 実体は int32。値 = 実数 × 256
export const FX_ONE = 256;
export const fx  = (n: number): Fx => Math.round(n * 256) | 0;   // データ読込時のみ使用
export const fxMul = (a: Fx, b: Fx): Fx => ((a * b) >> 8) | 0;   // 積
export const fxDiv = (a: Fx, b: Fx): Fx => (((a << 8) / b) | 0); // 商（0 方向切り捨て）
export const fxSqrt = (a: Fx): Fx => /* 整数ニュートン法。テスト T-M2-02 */;
```

- **1 マス = 村人 1 体分の幅 = `FX_ONE * 1`**（`07§1`）。マップ座標は Fx で持つ。
- 距離比較には `fxSqrt` を使わず**平方距離**で比較する（`distSq <= r*r`）。`fxSqrt` は令の遅延計算など表示・式で必要な箇所のみ。
- 割り算の丸めは**必ず 0 方向切り捨て**に統一。`Math.floor` と `| 0` を混在させない。

### 4.3 乱数 `Rng`

```ts
// sim/core/rng.ts  xorshift128（状態 4×uint32）
export class Rng {
  constructor(seed: number)
  nextU32(): number
  nextInt(maxExclusive: number): number   // モジュロバイアス除去済み
  nextFx(): Fx                            // [0, FX_ONE)
  clone(): Rng
}
```

- `World` は乱数ストリームを **用途ごとに分離**して持つ: `rngCombat`, `rngAi`, `rngMap`。
  戦闘の乱数消費回数が AI の乱数に影響しないようにするため（デシンク原因の定番）。
- マップ生成は `rngMap` のみを使い、生成後は触らない。

### 4.4 エンティティ

```ts
// sim/core/entity.ts
export type EntityId = number;   // 上位 16bit: generation, 下位 16bit: index
// Structure of Arrays。追加・削除は index の free list で再利用し、generation を +1。
export interface Entities {
  count: number;
  kind:      Uint8Array;    // Unit | Building | Resource | Projectile | Attachment
  owner:     Uint8Array;    // playerId (0-7), 255 = 中立
  typeId:    Uint16Array;   // units.json / buildings.json のインデックス
  x: Int32Array; y: Int32Array;         // Fx
  hp: Int32Array; hpMax: Int32Array;    // Fx
  morale: Int32Array;                   // Fx, 0..FX_ONE  (07§6)
  frontId:   Uint8Array;    // 0 = 所属なし, 1..6 = 戦域スロット
  manual:    Uint8Array;    // 1 = プレイヤーが手動操作中（令から外れる）
  // …詳細は T-M2-03
}
```

- **反復は必ず index 昇順**。削除時に配列を詰め替える（swap-remove）ことは**禁止**（順序が変わる）。free list 方式にする。
- 空間検索は 8×8 マスの**均一グリッド**（`sim/core/grid.ts`）。近傍問い合わせは常にセル → index 昇順で走査。

### 4.5 状態ハッシュ

```ts
// sim/hash.ts
export function hashWorld(w: World): number  // FNV-1a 32bit
```

対象: tick、各プレイヤーの資源 4 種・忠誠度・時代、全エンティティの `x,y,hp,morale,frontId`、戦域の中心と半径、各 rng の状態。
**毎 250 tick（10 秒）ごとに算出**して対戦相手と突き合わせ、不一致なら即座に「デシンク検出」を UI に出して試合を停止する（`T-M14-06`）。

### 4.6 システム実行順（毎 tick、この順序を変えない）

```
 1. applyCommands        入力を適用（生産指示・令のセット・手動指示）
 2. orderDelivery        令の遅延カウントダウン → 発効 (07§4)
 3. frontLifecycle       戦域の発生・成長・統合・分裂・消滅 (07§3)
 4. frontEnrollment      半径内の自軍を戦域に編入
 5. unitDecision         0.5s ごとの目標再選択（tick%12==entityIndex%12 で分散）(07§5)
 6. movement             経路追従・押し出し
 7. combat               攻撃判定・投射物・ダメージ (07§6)
 8. morale               士気の増減・退却 (07§6)
 9. economy              採集・搬入・農地枯渇・交易・相場 (07§8)
10. construction         建設・修理・跡地タイマー (07§9)
11. production           生産キュー・人口・研究・時代進化
12. loyalty              忠誠度の増減 (07§10)
13. victory              勝敗判定 (03§10)
14. cleanup              死亡処理・free list 返却・戦域スロット解放
```

`unitDecision` を tick で分散させるのは負荷対策。**分散のキーは `entityIndex % 12`** とし、乱数を使わない。

## 6. シミュレーション各機構の仕様

上流資料の規則を**実装可能な形に落としたもの**。ここに書かれた式・分岐がそのまま `sim/systems/*.ts` になる。

### 6.1 戦域（Front） — `frontLifecycle.ts` / `frontEnrollment.ts`

```ts
interface Front {
  slot: 1|2|3|4|5|6;         // 表示番号・色・キー割当と一致
  x: Fx; y: Fx;              // 中心（所属ユニットの重心。毎 tick 更新）
  radius: Fx;                // 15 → 最大 30 マス
  order: OrderId | null;     // 上段
  orderLower: OrderId | null;// 下段（二重旗のみ）
  pendingOrder: { id: OrderId; tier: Tier; deliverAtTick: number } | null;
  lastSwitchTick: number;    // 切り替え間隔の判定用
  lastEngageTick: number;    // 消滅判定用
  advantage: Fx;             // -FX_ONE..FX_ONE
  dmgDealt: number[]; dmgTaken: number[]; // 直近 10 秒のリングバッファ(250 tick)
  defected: boolean;         // 忠誠度による離反（令を無視）
}
```

**発生**: 敵味方の戦闘ユニットが半径 15 マス内に**それぞれ 3 体以上**いて、交戦（実ダメージの発生）が **2 秒（50 tick）継続**したら戦域化。
候補の中心は「その条件を満たしたユニット集合の重心」。同一 tick に複数候補があれば **重心座標 (y, x) の昇順**で処理（乱数を使わない）。

**成長**: `radius = clamp(15 + floor(所属ユニット数 / 4), 15, 30)` マス。

**統合**: 中心間距離 ≤ 20 マス → **slot 番号の小さい方が大きい方を吸収**し、**吸収した側（小さい方）の令が全体に適用**される。空いた slot は解放。

**分裂**: 所属ユニットのうち中心から 35 マス以上離れた集団があるとき、空き slot があれば新戦域として独立（令を引き継ぐ）。空きがなければその集団は `frontId = 0`（戦域外）。

**消滅**: `tick - lastEngageTick >= 375`（15 秒）で閉じる。所属ユニットは `frontId = 0` になるが**最後の令を保持して待機**する（`lastOrder` をユニット側に持たせる）。

**スロット不足**: 新規戦闘は戦域にならない。その場のユニットは `lastOrder` を継続、なければ既定行動「近くの敵に応戦」。

**優勢度**:
```
advantage = 0.5 * clamp((dealt - taken) / max(1, dealt + taken), -1, 1)
          + 0.5 * clamp(自軍残存兵力比 - 敵残存兵力比, -1, 1)
```
`advantage < -0.30` で警告（点滅）。兵力比は「現在 HP 合計 / 戦域に入った時点の HP 合計」。

**編入**: 半径内に入った自軍ユニットは自動でその戦域に編入。ただし `manual = 1` のユニットは編入しない。

**視界の例外**: 自軍が交戦している戦域は視界と無関係にミニマップに出る（`07§7`）。**敵の戦域は輪の数と位置のみ**が見える（中身の兵種・数は見えない）。囮が成立する根拠なので、この非対称を必ず守る。

### 6.2 令の遅延 — `orderDelivery.ts`

```
delaySec = clamp( (1.5 + dist * 0.02 + 伝令補正) * 復唱倍率 * 忠誠度ペナルティ, 0.5, 8.0 )
  dist       = 最も近い「令の発信点」から戦域中心までの直線距離（マス, 地形無視）
  発信点     = 本陣 ∪ 自軍の城（モンゴルは大天幕。畳んで移動すると発信点も動く）
  伝令補正   = 戦域内に「伝令」ユニットが 1 体以上いれば -1.0（重複しない）
  復唱倍率   = 研究「復唱」で 0.5、なしで 1.0
  モンゴル「駅伝」= dist の項を 0 にする
  忠誠度ペナルティ = 忠誠度 < 80% なら +2.0 秒（乗算ではなく加算。丸め前に足す）
```
計算順は `(1.5 + dist*0.02) → 伝令加算 → 復唱の乗算 → 忠誠度の加算 → 上下限クランプ`。
検算（`07§4` の例）: dist=200, 伝令あり, 復唱あり → `(1.5 + 4.0 - 1.0) * 0.5 = 2.25 秒` … **テスト `T-M9-02` にこの値を入れる**。

**切り替え間隔**: 同一戦域に次の令を出せるのは 6 秒後（研究「早馬」で 4.2 秒）。間隔内の入力は**無視**（キューに積まない。連打対策）。UI は砂時計を出す。

**二重旗**: 上段 1 枚 + 下段 1 枚まで。同段の重ね掛けは入力段階で拒否。

### 6.3 ユニットの判断 — `unitDecision.ts`

0.5 秒（12〜13 tick）ごとに、そのユニットの目標を選び直す。**評価はスコア最大の 1 つを選ぶ**。

```
score(candidate) =
    w.advance  * (前進で近づける度合い)
  + w.hold     * (持ち場からの距離のマイナス)
  + w.guard    * (護衛対象への近さ)
  + w.build    * (建設可能地点への近さ)
  + w.evade    * (被弾リスクのマイナス)
  + counterBonus(自分の role, 相手の role)      // 相性有利なら +
  + targetPriorityBonus(令の targetPriority)    // 略奪なら村人に大きく +
  - 0.2 * (他ユニットが既にその目標を選んだ数)  // 集中しすぎ防止
```

- 重みは `orders.json` の `weights`。令がない場合は既定重み（`advance 0.3 / hold 0.5`＝「近くの敵に応戦」）。
- `manual = 1` のユニットは**この処理を丸ごとスキップ**し、プレイヤーの指示だけを実行（`07§5`）。
- 令ごとの結果挙動は `07§5` の表どおり。特に:
  - **包囲**: 攻城兵器を先頭に、歩兵の `guard` を最大。兵器が下がると歩兵も下がる。投石系は**射線に味方を置かない**配置補正を入れる。
  - **略奪**: 戦闘ユニットを避けて回り込む（`avoidCombatUnits`）。**井戸・種籾蔵は自動ターゲットに含めない**。
  - **建設**: 村人の `build` 最大、兵は村人を護衛。前線に壁・塔を建て進める。
  - **後退**: `advance` を負にし `evade` 最大。士気の低い兵から順に下がる。

### 6.4 戦闘計算 — `combat.ts`

```
dmg = max(1, atk - defEffective) * counter * terrain * formation
  defEffective = pierce ? floor(def / 2) : def
  counter  = 有利 1.5 / 不利 0.7 / 等倍 1.0      ← role の組み合わせ表
  terrain  = 高所→低所 1.15 / 低所→高所 0.9 / 同 1.0
  formation= 範囲攻撃を密集隊列が受けると 1.4
  友軍被害 = 範囲攻撃の 50%（味方にも入る）
```

相性表（`03§7`。`role` × `role` の行列を `config.json` に持つ）:

| 攻撃側 role | 有利な相手 | 不利な相手 |
|---|---|---|
| spear（槍・長槍） | cavalry, beast | ranged, siege(aoe) |
| sword（刀剣） | spear, building | ranged |
| ranged | 近接歩兵全般（spear, sword） | cavalry, siege |
| cavalry | ranged, siege, villager | spear, camel |
| beast（ペルシアのみ） | spear（壁）, 密集歩兵 | gunpowder, bolt |
| siege | building, wall, 密集歩兵 | cavalry, 近接全般 |
| gunpowder | 重装甲, beast | cavalry |

式に**掛からない**補正（`07§6`）: 森の中の遠隔 = 射程 −25% / 水際の騎兵 = 速度 −30% / 散開 = 速度 −15%。

### 6.5 士気 — `morale.ts`

- `morale` は 0..FX_ONE。**HP 0 の前に morale 0 で退く**。
- 減少要因: 孤立（半径 5 マスに味方 0）/ 戦域が警告状態 / 直近 3 秒に半径 6 マス内で味方が 3 体以上死亡 / 令が届いていない（`pendingOrder != null` かつ戦域が劣勢）。
- 増加要因: 密集隊列 / 半径 8 マスに祈祷師 / 戦域が優勢 / 自軍建物・壁の内側。
- morale 0 → **10 秒間、最寄り拠点方向へ退却して回復**し、戻る。この間 `frontId` は保持する。
- これが「捨てる判断」を成立させる中核。**後退の令で畳めば戦力を全損しない**ことをテストで担保（`T-M8-07`）。

### 6.6 経済 — `economy.ts`

```
実効収集速度 = 基礎速度 × 研究倍率 × 文明倍率 × (1 - 運搬損失)
  運搬損失 = min(0.50, floor(片道距離マス / 4) * 0.05)
```
- 村人は 10 単位持つと最寄りの搬入点（町の中心・伐採所・採掘場・桟橋）へ歩く。
- 森・鉱脈・農地に埋蔵量（農地 1 面 = 食料 400）。**採った分だけ減る**。枯れた農地は木材半額で再建（自動再建オプション）。
- 市場相場: 100 単位買うごとに +3%、30 秒ごとに 1% 戻る。**全プレイヤー共通**。
- 交易: 金 = 片道距離 × 0.5 / 往復。交易路が戦域に重なると荷車が狙われる。
- 貢納（チーム戦）: 手数料 10%。
- 攻撃された村人は自動で最寄りの塔・櫓・城へ退避（設定で無効化可）。
- 人口: 家 +5 / 町の中心 +10 / 既定上限 200。攻城兵器 pop 3、戦象 pop 2。

### 6.7 建物・壁 — `construction.ts`

- 建設は村人数で加速: 1 人 1.0 / 2 人 1.7 / 3 人 2.3（逓減。式は `1 + 0.7 * (n-1)^0.85` を整数テーブル化して `config.json` に持つ）。
- 修理費は失った HP に比例、**建設費の 1/4 が上限**。
- **壊れた壁の穴はその試合中ずっと通り道**。建て直せるが同じ場所は建設時間 1.5 倍。
- 門は自軍・味方のみ通行可。攻城兵器は門か穴しか通れない。
- 塔・砲塔は村人を収容でき、収容中の村人は矢を放つ。
- 城 = 戦域スロット +1 かつ**令の発信点**。モンゴルの大天幕は移動可能な発信点（耐久は城の 60%）。
- 建設中の建物は HP が低く、壊されると資源は戻らない。
- 破壊跡地は数十秒残り、その間は同じ場所に建てられない。

### 6.8 忠誠と離反 — `loyalty.ts`

| できごと | 変化 |
|---|---|
| 掟一 碑の島で交戦 / 掟二 井戸破壊 / 掟三 種籾蔵破壊 / 掟五 逃亡村人を 30 秒以内に攻撃 | 各 **−25% / 回** |
| 町の中心を失う | **−5%** / 1 つ |
| 戦域を 3 つ以上同時に見捨てる（令を渡さず 60 秒放置し、その間に劣勢へ落ちた戦域の数） | **−10%**。後退で畳んだ分は対象外 |
| 時間経過 | **+1% / 30 秒** |
| 休戦の季を守り切る | **+15%**（オプション有効時のみ） |

閾値: `< 80%` → 令の遅延 +2 秒 / `< 50%` → 戦域 1 つが令を無視（`defected = true`。カードを差し替えても反応しない。既定行動のみ）/ `= 0%` → **敗北**。

離反対象の戦域の選び方は **slot 番号が最大のもの**（乱数を使わない）。

### 6.9 勝敗 — `victory.ts`

1. **制圧**: 相手の町の中心をすべて破壊
2. **碑の写し**: 帝国の世で記念碑（木1000/石1000/金1000）を建て **6 分（9,000 tick）守り切る**。建設開始時点で全プレイヤーに位置が公開される（唯一、情報を隠せない行動）
3. **服属**: 投了（`F10` メニュー）。キャンペーンでは分岐へ
4. **敗北**: 町の中心を全喪失、または忠誠度 0%。**戦域 0 本は敗北ではない**

### 6.10 マップ生成 — `sim/systems/mapgen.ts`（`rngMap` のみ使用）

順序を守る（`07§13`）:
1. 開始位置を円周上に等間隔配置（距離は必ず同一）。サイズは 1v1 で **200×200 マス**、8 人で **400×400 マス**、人数で線形補間
2. 各拠点から**同距離・同量**の 森／石／金／食料 を置く
3. 争点（追加の金鉱、豊かな森）を中央寄りに置く
4. 川・森・丘・水域を、上記を壊さないよう描く
5. 通行検査（全拠点間の到達性、隘路が 1 本だけになっていないか）。失敗したら**シードを +1 して作り直す**（最大 20 回、超えたら平野型にフォールバック）

マップ型 8 種: 内海 / 平野 / 河川 / 列島 / 隘路 / 草原 / 密林 / 碑の島。パラメータは `maps.json`。碑の島は**島内での交戦が掟一違反**になる特別領域フラグを持つ。

## 7. 描画層（`src/render`）

### 7.1 方針

- 斜め見下ろし（2:1 の擬似アイソメ）。タイル → 画面座標は `sx = (x - y) * TW/2`, `sy = (x + y) * TH/2`。
- **レイヤ**: 地形（オフスクリーンにキャッシュし、スクロール時はコピーのみ）→ 地形装飾 → 建物・ユニット（Y ソート）→ 投射物 → エフェクト → 戦域の輪 → 選択円・体力バー。
- **Y ソート**は `sy` 昇順、同値は `EntityId` 昇順（ちらつき防止）。
- 補間: `stepWorld` 前の座標を `prevX/prevY` に保持し、描画時に `alpha` で線形補間。
- スプライトは**方向 8 × アニメ 4〜8 フレーム**。アトラス（1 文明 1 枚）に詰めて `drawImage` の呼び出し回数を抑える。
- **60fps / 400 体**の予算: 1 フレーム 16.6ms のうち描画 10ms 以内。超えたら `T-M18-02` の最適化（ダーティ矩形・LOD・遠景のアニメ間引き）を行う。

### 7.2 視界・霧

- 視界は 1 マス単位のビットマップ 3 状態（未探索 / 既知 / 可視）。
- **既知**は「最後に見た時点の地形と建物の形」のみ。今いる敵・建物の HP・破壊済みかは見えない（`07§7`「建物は嘘をつく」）。
- 描画は視界バッファをぼかしたマスクを乗算。**視界更新は 5 tick ごと**で十分（見た目に影響しない範囲で負荷を落とす）。

### 7.3 戦域の可視化

- 戦域の色は**陣営色とは別系統**の 6 色固定。ミニマップの輪・部隊の足元・スロットの旗・リプレイのレーンで一貫（`05§15`）。

## 10. AI（`src/ai`）

**AI もプレイヤーと同じ `Command` しか出せない**。視界の透視・資源の増量は**しない**（`07§11`）。上げるのは判断間隔と使う仕組みの範囲だけ。

| 段階 | 使う仕組み | 判断間隔 |
|---|---|---|
| 1 素人 | 内政のみ。攻めない | 8 秒 |
| 2 見習い | 戦域 1 つ。突撃と死守だけ | 6 秒 |
| 3 諸侯 | 戦域 2〜3。令 4 種、時代進化 | 4 秒 |
| 4 将軍 | 戦域を上限まで。囮を立てる | 2 秒 |
| 5 総大将 | 固有令・二重旗・攻城。令の遅延もプレイヤーと同条件 | 1 秒 |

構造:
```
ai/
├─ AiPlayer.ts       # 判断間隔ごとに think() を呼ぶ
├─ econGoals.ts      # 村人配分・家の建て増し・進化タイミング
├─ militaryGoals.ts  # 兵種構成（相手文明の「穴」から逆算）
└─ frontPolicy.ts    # 各戦域への令の選択・捨てる戦域の決定・囮
```
- AI は `rngAi` のみを使う。**AI が乱数を引く回数が戦闘結果に影響しないこと**をテストで確認（`T-M13-05`）。
- 「令を切り替えた直後の 6 秒」は AI にも同じく隙になる（`07§11`）。ここを短縮するズルを入れない。

## 11. 通信（`src/net` + `server/relay.ts`）

### 11.1 ロックステップ

- 1 秒 = 25 フレーム。各フレームの**入力のみ**を交換（クリック座標と令の番号）。ユニット座標は送らない。
- 全員の入力が揃ってから次のフレームを進める。**入力遅延 3 フレーム（120ms）**先の tick 宛に入力を送る。
- サーバはゲームロジックを持たない**中継のみ**。ルームは URL の `#room=xxxx` で共有、アカウント登録なし。

### 11.2 パケット

```ts
type C2S = { t:"join"; room:string; name:string }
         | { t:"ready" }
         | { t:"input"; tick:number; cmds:Command[] }
         | { t:"hash";  tick:number; hash:number };
type S2C = { t:"welcome"; playerId:number; seed:number; setup:MatchSetup }
         | { t:"start";   startTick:number }
         | { t:"input";   tick:number; byPlayer:Record<number, Command[]> }
         | { t:"desync";  tick:number; hashes:Record<number, number> }
         | { t:"left";    playerId:number; atTick:number };
```

### 11.3 切断（`07§12`）

- 席は **120 秒**保持。その間は AI が代行（令は最後の状態を維持）。
- 代行開始の判定は「**入力が 3 秒届かなかったフレーム番号**」。全端末が**同じフレームで同じ判断**をするので決定論は崩れない。
- 戻れば操作を引き継ぐ。戻らなければ AI が続行。
- **アンドゥは存在しない**（入力を確定させてから進むため）。誤った令は上書きで直す。

### 11.4 観戦

観戦者は入力を送らない → 何人増えても試合に影響しない。全プレイヤーの視界と全戦域の令の履歴を見られる。

## 12. リプレイ（`src/replay`）

- 保存するのは映像ではなく**入力の記録**。フォーマット `.mtr`（JSON + gzip）:
  ```json
  { "version": 1, "seed": 12345, "setup": { }, "dataHash": "…",
    "inputs": [ { "tick": 0, "byPlayer": { "0": [ ] } } ],
    "hashes": [ { "tick": 250, "hash": 305419896 } ] }
  ```
- `dataHash` は `src/data/*.json` 全体のハッシュ。**データを変えた後の古いリプレイは再生を拒否**して警告を出す（黙って壊れた再生をしない）。
- リプレイ画面の主役は**戦域レーン**（`05§14`）。レーンが伸びている時間 = その戦域が立っていた時間。令を出した時刻と届いた時刻のずれを表示。
- 倍速 0.5〜8 倍。倍速は `tickBudget` を増やすだけで実装する。

### 14.3 バランス調整時のルール

JSON の数値変更でゴールデンリプレイのハッシュは**必ず変わる**。この場合のみ、以下の手順で期待値を更新してよい。

1. 変更前に `npm run test:golden` が緑であることを確認
2. JSON を変更
3. `npm run golden:rebase` で期待ハッシュを再生成
4. コミットメッセージに `[rebase-golden]` を付け、**何をどう変えたか**を本文に書く

ロジック変更でハッシュが変わった場合は **rebase してはいけない**。バグとして調査する。

## 16. 実装上の注意（過去にハマりやすい箇所）

1. **`sim` に浮動小数を 1 箇所でも混ぜると、数十分後にデシンクする。** 発覚が遅いので M2 の lint とテストを手抜きしない。
2. **戦域の統合・分裂は順序依存でデシンクしやすい。** 候補の処理順を必ず「座標 (y, x) 昇順 → EntityId 昇順」で全順序に固定する。
3. **`unitDecision` の tick 分散を乱数でやってはいけない。** `entityIndex % 12` を使う。
4. **令の遅延は「押した瞬間に効かない」ことがゲームの肝。** UI で遅延を隠したり先行反映したりすると設計が崩れる（`06§4`「連打しないでください」）。
5. **敵の戦域は輪の数と位置のみ見える。** ここを漏らすと「囮」が成立しなくなる（`07§7`）。
6. **`Ctrl`+`A` は戦域の兵を含めない。** 全戦線の自律が一斉に止まるのを防ぐため（`06§5`）。
7. **「略奪」は井戸・種籾蔵を自動で狙わない。** 掟破りは手動選択時のみ（`03§3`）。
8. **スロット上限を超えた戦闘は「起きる」。** 起きないようにしてはいけない。令が届かないだけ（`07§3`）。
9. **AI にズルをさせない。** 難易度は判断間隔と使う仕組みの範囲だけで作る（`07§11`）。
10. **HUD の位置は絶対に動かさない。** 目線の移動先を毎回同じにすることが最優先（`05§1`）。
