## [解決] 固有令のフラグが未適用（7 件）→ 実装済み（2026-08-09）
7 件すべて実装され、エリート 8 種の特性も入った。実装の要点:
- 令の名前で分岐せず、`orders.json` の `flags` の**値の型**で解釈する
  （数値=倍率/比率、真偽値=有無、オブジェクト=資源ごとの毎秒量）。
  二重旗のときは 倍率=両段の積 / 比率=両段の最大 / 真偽=論理和。
- 検算: 陣立て 3456→2943 / 火計 対建物のみ ×1.35 / 上陸 3456→4147 /
  交易 25 tick でちょうど 金 1.5 / 奉納 撃破コスト×0.5 が資源に /
  圧壊 騎兵→槍 895→1280（不利 0.7 を等倍に戻す）/ 方陣 士気 0 でも退却しないが HP 0 では死ぬ
- 解釈を決めた 2 件:
  - **上陸**: 「強襲」の内容が資料にないので、浅瀬・湿地に足を置いている間だけ
    (a) 低所→高所の 0.9 を等倍に戻す (b) 与ダメージ ×1.2。
    「岸へ攻め上がる不利を消す」のが上陸の意味だという読み。
  - **圧壊**: `03§7` の獣兵「槍兵に止められない突破力」に合わせ、
    相性倍率を**等倍に寄せる**（不利 0.7→1.0、受ける側の 1.5→1.0。有利は伸ばさない）。
    押し出しは戦象の特性 `knockback` が担うので令には持たせなかった。
- 残り 2 フラグ未適用: `formationKeep`（配置 = movement 担当）/
  `requiresWaterFront`（令を出す側の検査 = command / UI 担当）。
  「`orders.json` の flags は全部どこかで読まれている」テストに明示リストとして残してある。

## [判断] 戦域の細部で資料に規定がない 3 点
`07§3` が書いていない挙動。実装で決めた内容を記録する。
`config.json` にキーとして出すことも検討したが、**どこからも読まれないキーは
「変えても効かない」罠になる**ので、コード側の規則として持ちここに記録するだけにした。
挙動を変えたくなったら `sim/systems/frontLifecycle.ts` を直すこと。

| 項目 | 決めた挙動 | 根拠 |
|---|---|---|
| 村人を戦域に編入するか | **する** | `07§3` は「半径に入った自軍ユニットは自動でその戦域に編入」と書いており兵に限定していない。令「建設」が村人に壁・塔を建てさせる仕様（`07§5`）とも整合する |
| 何体から「集団」として分裂するか | **1 体でも分裂する** | `07§3` は「中の部隊が 35 マス以上に離れると分裂」とのみ。閾値を設けると「離れた 1 体が戦域に属し続ける」ことになり、優勢度の分母が歪む |
| 所属 0 になった戦域 | **即閉じる** | 消滅条件は「交戦が 15 秒起きなければ」だけだが、中身が全滅した戦域を 15 秒残すとスロットが無駄に埋まる。閉じた時点で `lastOrder` は残る（`07§3`）ので挙動上の損はない |

- 記録日: 2026-08-09

## [矛盾] 唐の研究コスト割引が二重に掛かっていた
- `03§3`（固有建物）: 翰林院 = **学舎の置き換え**。「研究が 20% 速く、20% 安い」（数値が明記されている）
- `02` / `03§5`（文明の内政ボーナス）: 唐 = 「技術研究が安い」（数値なしの散文）
- 両方をデータに入れると、翰林院での研究に `researchCostMul 0.8` が 2 回掛かり
  **0.64 倍**になっていた（M6 の効果適用エンジンは型どおり両方掛けるだけなので、
  データ側の重複がそのまま出る）。
- 採用: **数値が明記されている建物側（翰林院）だけを残し、`civs.json` の唐の
  `econBonus` を空にした**（手順書 §0.4 の優先順位に従い、`03` の明示値が散文に勝つ）。
  翰林院は学舎の置き換えなので、唐の研究は結果として実際に安くなる ＝
  「技術研究が安い」という記述は満たされる。
- 副作用: 鍛冶場・伐採所など**学舎以外での研究は安くならない**。
  資料の散文は「技術研究が安い」と一般化しているので、ここは解釈が分かれる。
  唐を全体的に安くしたいなら、翰林院側の `researchCostMul` を外して
  文明ボーナスに戻すのが対称的な選択肢（M18 のバランス調整で判断）。
- 記録日: 2026-08-09

## [判断] 戦域スロットの加算元をデータ側に一本化した

  `castle`/`great_tent` の `frontSlotBonus`、`techs.json` の `hatazao` の

## [保留] 市場の売却側の規定が資料にない
- `07§8` は「ある資源を 100 単位買うごとに価格 +3%。30 秒ごとに 1% ずつ元に戻る」と
  **買う側だけ**を規定している。売却したときに
  (a) 受取額が買値と同じか（`economy.marketSellRatio`）、
  (b) 売却で相場が下がるか（`economy.marketSellMovesPrice`）
  は書かれていない。
- 暫定: `marketSellRatio = 1.0` / `marketSellMovesPrice = false`（＝売却は相場を動かさない）。
  JSON のキーとして外に出してあるので、バランス調整で変えられる。
- 判断が必要な理由: 売却が相場を下げると「売って買い戻す」で相場を操作できてしまう。
  一方で下げないと、余剰資源を金に換える動きが常に得になる。M18 のバランス調整で決める。
- 記録日: 2026-08-09

## [保留] 相場倍率 priceMul の精度
- 相場は Fx（1/256 刻み）で持っているため、「30 秒ごとに 1% 戻す」が 3/256 = 1.17% に丸まる。
- 実用上の影響は小さいが、より忠実にするなら `priceMul` だけ別スケール（Q16）で持つ必要がある。
- 記録日: 2026-08-09

## [判断] 固有令の段の割り当て
- 手順書 T-M9-08 の指示による。`07§4` は「上段 = 移動・配置の方針（どこへ行くか・下がるか・
  何を建てるか）」「下段 = 攻撃目標の優先（何を狙うか・誰を護衛するか）」と定義し、
  固有令については **ローマ「方陣」= 上段 / マリ「交易」= 下段** のみを明記している。
  残る 6 件は「その令が何を変えるか」を上の定義に当てて決めた（`game/src/data/orders.json`）。
- 判定の指針: **隊形・前進量・移動範囲を変える令は上段、狙う対象の優先順位や撃破の扱いを
  変える令は下段**。これで上段どうし・下段どうしが排他になり、二重旗の組み合わせが意味を持つ。

| 令 | 文明 | 段 | 根拠 |
|---|---|---|---|
| 陣立て `jindate` | ヤマト | 上段 | 「防御隊形で被害を軽減」＝隊形（dense）と持ち場の重みを変える令。攻撃目標は既定のまま。配置の方針なので上段。下段の包囲・略奪と重ねて「固く構えて門を叩く」が成立する |
| 火計 `kakei` | 唐 | 下段 | 「建物へのダメージが増える」＝狙う対象を建物へ寄せる令。`targetPriority` の先頭を `building` にする。移動方針は変えない。包囲と同じ性質なので下段（＝包囲とは排他） |
| 上陸 `jouriku` | ヴァイキング | 上段 | 「水辺の戦域に強襲をかける」＝船から岸へ、どこへ行くかを決める令。前進の重みを最大にする移動の方針そのものなので上段 |
| 奉納 `hounou` | アステカ | 下段 | 「撃破数が資源に変わる」＝隊形も前進量も変えず、建物よりも生きた敵ユニットを撃破する方へ優先を寄せる令。攻撃目標の扱いを変えるので下段 |
| 圧壊 `assai` | ペルシア | 上段 | 「正面の敵陣を押し崩す」＝密集して直進する隊形＋前進最大の令。突撃の上位互換的な移動・配置の方針なので上段（＝突撃とは排他になるのが妥当） |
| 遊撃 `yugeki` | モンゴル | 上段 | 「戦域を跨いで移動し続ける」＝戦域の枠を越えて動き回るという移動の方針そのもの。上段にすることで下段（略奪など）と重ね、「動きながら村人を狙う」というモンゴルらしい運用が作れる |

- 結果の内訳: 固有令 8 件のうち **上段 5（陣立て・方陣・上陸・圧壊・遊撃）／下段 3（火計・交易・奉納）**。
  各令の `note` にも同じ根拠を `【段の判断】` 付きで残してある（テスト `data.orders.test.ts` で検証）。
- 記録日: 2026-08-09
