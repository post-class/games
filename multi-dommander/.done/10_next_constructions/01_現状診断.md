# 01 現状診断 — なぜ「チープ」に見えるのか

現行 multi-dommander（約4,800行 / TypeScript + Three.js + 自作ECS）を、コードを実際に読んで診断した。
結論を先に言うと、**土台の設計は良い。チープさは「量産的な欠落」＝見た目・手触り・音・演出・コンテンツ量の不足に集中している**。だから“作り直し”ではなく“肉付け”で化ける。

---

## 1. まず、良い土台（伸ばすべき資産）

これらは既に整っており、後続の全計画がここに乗る。

| 資産 | 場所 | なぜ効くか |
|---|---|---|
| 自作軽量ECS | `src/ecs/`（World/Component/System） | 機能追加が疎結合。演出・武装・AIを system 単位で足せる |
| 固定dt物理 + 可変dt描画 | `src/game/Game.ts:45-70` | 挙動が安定。ヒットストップ等の `timeScale` 拡張点も明確 |
| データ駆動の機体定義 | `src/game/ships/shipDefinitions.ts`, `ShipDefinition.ts` | “データを足せば機体が増える”。武装/耐久の拡張余地 |
| データ駆動のミッション | `src/game/mission/missions.ts`, `MissionDefinition.ts` | 目標/ウェーブ/分岐がデータ。種別追加が容易 |
| **GLTF差し替え口が既存** | `src/render/MeshFactory.ts:114-143` | `visual.kind:"gltf"` にURLを与えるだけで実モデル化。フォールバックも実装済み |
| イベントバス | `src/util/EventBus.ts` | 演出・音・進行を疎結合に“ぶら下げ”られる中枢 |
| 陣営/ターゲティング/僚機指令/難易度 | `factions.ts`, `TargetingSystem.ts`, `AISystem.ts`, `Settings.ts` | ゲームの骨格は既に動く |
| 30件のユニットテスト | `tests/` | 物理・リード予測・衝突・ミッション・分岐を担保。改修の安全網 |

**含意:** 「素晴らしい」への道は、この骨格を壊さずに演出・コンテンツを重ねること。

---

## 2. チープさの主因（コード根拠つき）

### 2.1 描画に“仕上げ”が無い（最大要因）

- **ポストプロセス皆無。** `src/game/Game.ts:67` は `this.render.renderer.render(scene, camera)` を素で呼ぶだけ。ブルーム／トーンマッピング／アンチエイリアス後段／ビネットが一切ない。宇宙ゲームの「映え」はブルームでほぼ決まるため、これだけで安っぽさの大半が生じる。
- **背景が平板。** `src/render/SkyboxStars.ts` は `Points`（`size:40`）で球殻に点を撒くだけ。星雲・遠景の惑星・太陽・奥行きが無い。`SceneSetup.ts:22` の背景は単色 `0x01030a`。
- **質感が出ない。** `SceneSetup.ts:39-45` は方向光2＋環境光1の素朴な3灯。環境マップ（IBL）が無いため `MeshStandardMaterial`（`MeshFactory.ts:39`）の金属感が死んでいる。
- **機体はプログラマアート。** `MeshFactory.ts` は Cone/Box/Sphere の組み合わせ。4機種すべて `visual.kind:"primitive"`（`shipDefinitions.ts`）。

→ 対策は [`04_技術仕様_描画と手触り.md`](./04_技術仕様_描画と手触り.md)（P1）／[`06`](./06_技術仕様_コンテンツとAI.md)（P4 実アセット）。

### 2.2 “手触り（ジュース）”が無い

- **爆発が発光球1個。** `src/game/systems/ExplosionSystem.ts:35-51` は単一の加算合成スフィアを膨らませて消すだけ。デブリ・衝撃波・火花・煙・閃光が無い。被弾も同じ球を小さく出すのみ（`ExplosionSystem.ts:36`）。
- **カメラが淡白。** `src/render/CameraRig.ts` は後方オフセットへ lerp 追従するだけ。シェイク・FOVキック・ヒットストップが無く、撃墜しても“手応え”が返らない。
- **フィードバックUIが機能止まり。** ヒットマーカー・キルフィード・被弾ビネット・画面フラッシュが未実装（`HudView.ts` は計器表示のみ）。
- **トレイル/マズルフラッシュ無し。** 弾は伸ばしたスフィア（`MeshFactory.ts:100-111`）、エンジンは静的な発光球（`MeshFactory.ts:82-94`）。

→ 対策は [`04_技術仕様_描画と手触り.md`](./04_技術仕様_描画と手触り.md)（P2）。

### 2.3 音が“ピコピコ”

- **合成SE4種のみ。** `src/game/AudioManager.ts` は gun/missile/hit/explosion を `tone()`/`noise()` で鳴らすだけ。BGM無し、エンジン音無し、警報無し、無線/VO無し。単一 `master` gain 直結で**空間音響（定位）も無い**——`hit`/`destroyed` は `position` を持つのに未使用。

→ 対策は [`05_技術仕様_オーディオ.md`](./05_技術仕様_オーディオ.md)（P3）。

### 2.4 コンテンツ量と戦術の薄さ

- **ミッション3本・直線分岐。** `src/game/mission/missions.ts`（patrol/escort/strike）。`CAMPAIGN`（`missions.ts:141-148`）は完全直線で、失敗は常に `retry`——「選択」も「敗北の物語」も無い。
- **機体4種／武器2種。** rapier/dralthi/transport/gratha。武器はエネルギー砲1＋単純追尾ミサイル1のみ（`WeaponSystem.ts`, `MissileSystem.ts`）。ロードアウト・対抗手段（チャフ等）・武装グループが無い。
- **AIが単一戦術。** `src/game/systems/AISystem.ts` は5状態FSM（Idle/Pursue/Attack/Evade/Form）だが、遷移は距離・照準ドット・タイマーだけの1関数（`AISystem.ts:317-339` 付近）。回避機動のバリエーション・編隊戦術・士気・エースが無い。

→ 対策は [`06_技術仕様_コンテンツとAI.md`](./06_技術仕様_コンテンツとAI.md)（P4/P5/P6）。

### 2.5 メタ進行・物語の不在

- **セーブは最小限。** `src/game/SaveManager.ts` は `missionId`/`totalKills`/`cleared[]` のみを localStorage 保存。パイロット名簿・勲章・アンロック・装備が無い。
- **人間ドラマが無い。** `MissionScreens.ts` はテキストのブリーフィング/デブリーフのみ。キャラクター・僚機との関係・階級・授与式・ミッション間の会話が無く、「戦う理由」が育たない。ウィングコマンダーの魂そのものが未実装。

→ 対策は [`07_技術仕様_メタ進行と物語.md`](./07_技術仕様_メタ進行と物語.md)（P7）。

## 3. 診断まとめ

```
チープさの内訳（体感寄与のイメージ）
  見た目の仕上げ不足 ████████████  ← P1 で最速に効く
  手触り(ジュース)無し ██████████   ← P2
  音の貧弱さ          ███████       ← P3
  コンテンツ/戦術の薄さ █████         ← P4-P6
  物語/メタの不在      █████         ← P7
```

- **良い骨格 × 量産的な欠落** という構図。骨格（ECS/データ駆動/GLTF口/イベントバス）は活かせる。
- **最速で効くのは P1〜P3**（見た目・手触り・音）。ここを終えるだけで「安っぽい」評価はほぼ覆る。
- コンテンツ・物語（P4〜P7）は骨格のデータ駆動性を使って積み増す領域で、量が“面白さ”に直結する。

次に読むべきは、目指す姿を定義する [`02_ビジョンと設計の柱.md`](./02_ビジョンと設計の柱.md)、そして順序を決める [`03_ロードマップ.md`](./03_ロードマップ.md)。
