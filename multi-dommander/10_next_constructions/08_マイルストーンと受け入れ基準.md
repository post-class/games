# 08 マイルストーンと受け入れ基準

本紙は各フェーズの「完了の定義（DoD）」・マイルストーン・リスク・テスト方針をまとめる。
フェーズの内容と順序は [`03_ロードマップ.md`](./03_ロードマップ.md)、技術詳細は `04`〜`07` を参照。

---

## 1. 全フェーズ共通の完了条件（Definition of Done）

どのフェーズも、以下を満たして初めて「完了」とする。

- [ ] `npm run build`（`tsc --noEmit` + vite build）が通る。
- [ ] `npm test`（既存30件のユニットテスト）が緑。挙動を変えた場合はテストを更新し、新ロジックには新テストを追加。
- [ ] 対象シーンで **60fps を維持**（性能計測オーバーレイ=P0 で確認。中位ノートPC内蔵GPU基準）。
- [ ] メモリリークが無い（ミッション再入場を5回繰り返してもヒープが単調増加しない。VFX/音/エンティティが確実に解放される）。
- [ ] 既存の操作・セーブとの後方互換を壊さない（壊す場合は移行処理を用意。例: セーブv2）。
- [ ] そのフェーズ単体で「前より良い」出荷可能状態（縦切り原則）。

## 2. マイルストーン（節目）

| Milestone | 含むフェーズ | 一言での到達状態 | 検証の要 |
|---|---|---|---|
| **M0 基盤** | P0 | イベント語彙・VFXプール・性能計測・timeScale が入り、テスト緑 | ビルド/テスト、オーバーレイ表示 |
| **M1 “見て分かる”** | P1・P2 | スクショ1枚で「チープでない」。撃墜に手応え | 静止画レビュー＋体感チェック（§4） |
| **M2 折り返し点** | P3 | 見た目・手触り・音が揃い「完成した瞬間」を感じる | 30秒デモ動画 |
| **M3 実在感** | P4 | 実モデル機体とキャピタルシップで戦場にスケール | GLTF読み込み・破壊可能サブシステム |
| **M4 空戦の奥行き** | P5 | 武装選択・回避機動・エースで読み合いが生まれる | ロードアウト→交戦の一連 |
| **M5 戦役** | P6 | 勝敗で分岐する複数ミッションを通しでプレイ可能 | 分岐グラフの通し確認 |
| **M6 作品化** | P7 | 名簿・勲章・ミッション間ドラマで「戦う理由」が宿る | 僚機戦死→物語反映の通し |
| **M7 磨き** | P8 | UI/演出/最適化が整い、公開できる品質 | オプション・モバイル・配布 |

**最重要マイルストーンは M2（P1〜P3完了）。** ここが「チープ⇄素晴らしい」の分水嶺。

## 3. フェーズ別の受け入れ基準（抜粋）

各技術仕様に詳細な基準があるため、ここでは横断的に見る要点のみ。

### P0 基盤整備
- `EventBus` に新イベントを追加してもビルド/テストが緑。
- VFXマネージャがプールから再利用し、爆発を60回連続生成してもGCスパイクでフレーム落ちしない。
- `timeScale` を 0.2 にすると物理・演出が一様にスローになり、1.0で完全復帰。

### P1 見た目の革命
- `EffectComposer` 経路でブルーム/AA/トーンマッピングが効き、素の `renderer.render` との差がスクショで明白。
- 背景に星雲・遠景天体が入り、単色背景でない。
- ポストプロセス有効時も対象シーンで60fps維持（`UnrealBloomPass` の解像度スケールで調整）。

### P2 戦闘の手触り
- 撃墜時に「多層爆発＋シェイク＋（トドメ時）ヒットストップ」が発生。
- 被弾でビネット/フラッシュ、命中でヒットマーカー、撃墜でキルフィード。
- 高速弾のトレイルが残像として視認でき、既存の線分-球スイープ衝突（`tests/collision.test.ts`）は維持。

### P3 音の世界
- 敵と交戦するとBGMが戦闘レイヤーへクロスフェード、離脱で平時へ戻る。
- 敵/弾/爆発が左右・前後に定位（`PannerNode`）。ミサイル被ロックで警報。
- Master/Music/SFX/Voice の音量が `Settings` に保存され、次回起動で復元。

### P4〜P6 コンテンツ／AI
- GLTF機体が `visual.kind:"gltf"` で差し替わり、失敗時はフォールバック表示（既存機構）。
- キャピタルシップのサブシステムを個別破壊でき、無力化で目標達成。
- 新武装（ダムファイア/熱源追尾/魚雷/対抗手段）がロードアウトで選択でき、シーカーとチャフが相互作用。
- AIが複数の回避機動を状況で使い分け、士気低下でエジェクト。
- 勝敗でキャンペーンが別ミッションへ分岐（`retry` 以外の経路が動く）。
- 新ミッション種別（要撃/偵察/無力化/防衛/離脱/時間制限）がデータ定義で成立。

### P7 メタ進行と物語
- 僚機が戦死すると名簿に永続反映され、二度と出撃しない（パーマデス）。
- ミッション間の会話シーンが再生され、選択が `campaignState` のフラグに反映。
- 撃墜数で階級・勲章が授与され、授与シーンが表示。
- セーブv1が自動でv2に移行し、既存進捗を失わない。

## 4. 体感チェックリスト（数値化しにくい品質の門番）

M1〜M2で特に重要。実際に遊んで○×で判定する。

- [ ] 起動後30秒以内に「おっ」と思う画があるか。
- [ ] 1機撃墜して「もう1機やりたい」と反射的に思うか。
- [ ] 被弾したとき、体でヒヤッとするフィードバック（画面/音）があるか。
- [ ] アフターバーナーで「速い」と感じるか（FOV/音/流れる背景）。
- [ ] 特定の僚機を「守りたい」と思う瞬間があるか（M6）。

## 5. リスクと緩和

| リスク | 影響 | 緩和策 |
|---|---|---|
| **ポストプロセスで性能低下**（特にブルーム/モバイルGPU） | P1でfps割れ | 解像度スケール・ブルーム段数を落とす画質プリセット（P8）。性能計測(P0)で常時監視 |
| **VFX/音のオブジェクト増でGCスパイク** | 戦闘中カクつき | P0のプーリングを全VFX/音の前提に。上限＋LRU再利用 |
| **アセット調達の停滞**（GLTF/音源のライセンス・品質） | P3/P4が遅延 | 「仕組み先行・素材後追い」。CC0(Kenney/Quaternius等)を既定、プレースホルダで疎通 |
| **スコープ拡大で未完** | 全体が中途半端 | 縦切り原則。M2（P1-P3）を最優先の出荷点に固定。P8/対戦はストレッチ |
| **セーブ形式変更で既存進捗破損** | ユーザー体験毀損 | versioned セーブ＋`migrate()`（[`07`](./07_技術仕様_メタ進行と物語.md)）。移行失敗時は安全に初期化しバックアップ保持 |
| **既存物理/衝突/AIのリグレッション** | 手触り劣化・バグ | 既存30テストを常時緑に保つ。挙動変更時はテスト先行更新 |
| **ブラウザ自動再生ポリシー**（音が出ない） | P3が無音 | 初回ユーザー操作で `resume()`（[`05`](./05_技術仕様_オーディオ.md)）。キー以外の操作でも有効化 |

## 6. テスト方針

- **ユニット（vitest, 既存 `tests/`）**: 物理積分・ピッチ規約・リード予測・ダメージ・衝突・ミッション目標・キャンペーングラフ。新ロジック（武装シーカー、分岐、セーブ移行、脅威度算出、勲章判定）に**新規テストを追加**する。
- **ビジュアル/演出**: 自動化しにくいため、代表シーンのスクリーンショット比較（手動レビュー）＋ §4 体感チェック。
- **性能**: P0の計測オーバーレイで各マイルストーンのfps/ドローコール/パーティクル数を記録し、退行が無いか節目で確認。
- **プレイスルー**: 各マイルストーンで「通し1回」を実施し、進行・分岐・セーブ・解放が破綻しないか確認。

---

## 7. まとめ

- 共通DoD（ビルド/テスト/60fps/リーク無/後方互換/縦切り）を毎フェーズ満たす。
- **M2（P1〜P3）が最重要の分水嶺**。ここを最優先で確実に通す。
- 最大のリスクは「性能」と「スコープ拡大」。プーリングと縦切り原則で抑える。
- 骨格の安全網（既存30テスト）を緑に保ち続けることが、大胆な肉付けを可能にする。
